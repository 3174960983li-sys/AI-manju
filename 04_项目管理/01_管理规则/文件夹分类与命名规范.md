# 文件夹分类与命名规范

生效依据：用户确认五类方案，并明确“先统一一级、二级分类；作品内部后续逐项整理”，随后授权执行。生效日期：2026-10-25。

|---|---|---|
| 01_作品项目 | 正式作品名，如无限杀戮 | 该作品的剧本、设定、资产、分镜、媒体和交付；现有作品内部不批量调整 |
| 02_制作方法 | 01_流程规范 | SOP、操作标准、检查流程和共同契约 |
| 02_制作方法 | 02_专业技能 | 完整Skill包、职责说明、能力映射、使用入口；内部标准结构保留 |
| 02_制作方法 | 03_提示词库 | 可复制、复用的指令与提示词方法；特定作品的投喂稿留在作品中 |
| 02_制作方法 | 04_通用模板 | 空白表单和可反复填写的模板；填写后的文件归其作品或任务 |
| 03_参考资料 | 01_书籍教程 | 书籍、教程、原始参考包及书库索引 |
| 03_参考资料 | 02_知识笔记 | 阅读提炼、专业笔记及知识文档；与可直接执行的制作方法区分 |
| 03_参考资料 | 03_案例分析 | 跨项目的案例研究与参考分析；实际制作及管理验收记录不因名为案例就搬来 |

| 04_项目管理 | 02_任务记录 | 任务状态、实施验收、实验记录、检查记录与盘点清单 |

| 05_文件整理 | 03_停用归档 | 已替代的方案、历史入口、原停用资料及本次迁移备份；不自动到期删除 |

## 命名标准

1. 一级仅允许表中五类；不再新增平行的“资料库、知识库、历史库、素材中心”等入口。
2. 一级和二级分类名称使用“两个半角数字＋半角下划线＋中文类别”，例如 `02_制作方法/01_流程规范`。编号只控制同层显示顺序，不表示必须按顺序执行。
3. 同层编号不重复；同一概念只使用表中一个标准名称。名称尽量四至六个汉字，清楚比硬凑字数更重要。
4. 作品目录直接使用正式作品名，不加编号、书名号、版本和日期；作品名有禁止字符时另定合法显示名，不擅改作品身份。
5. 主题目录使用稳定用途名，例如“人物一致性”；内容少时直接放文件，确有内容后再增加主题子目录。
6. Skill技术目录、`references`、`scripts`、`assets`、`agents`等和软件工程内部结构保持其标准名称。中文分类统一，不强制把软件所需英文目录中文化。
7. 本轮只规范一级和二级分类。第三层及更深的现有业务目录、作品内部和完整候选包保留，后续逐项整理，不宣称本轮已全层统一。
8. 禁止含糊名称，如“新建文件夹、最终最终版、修改后、杂项”；不使用Windows禁止的字符，避免尾随空格和句点。
9. 分类目录不加日期或版本号。文件按用途命名，常用入口保持稳定名称；有必要的独立文件快照可使用“主题_V1.0_2026-10-25”。当前既有文件不因本轮分类调整全部改名。

## 保存与整理

每份制作方法保留一个权威源；其他位置用链接或明确的发布副本。不要为了分类制造第二份可编辑原件。资料内容已被提炼为方法时，原书保留在参考资料，提炼的方法进入制作方法，两者保留来源关系。

只做过文字试跑的Skill仍标明适用范围，不因搬进制作方法就升级为正式验证通过。候选包进入待确认项不表示被认定无效。

已确认停用的资料进入停用归档；未知项进入待确认项；作品原稿、书籍和媒体不得仅因日期较早、同名或哈希相同被删除。迁移先记录来源、目标和内容校验值，修正受影响引用；不建立旧一级目录的兼容联接，以保持根目录恰好五类。

根目录仅保留 `00_使用说明.md` 和工具需要的 `AGENTS.md` 两份入口文件，其他方案、记录和工具归入相应分类。
