# 编写与交付规范

## 1. 优先解决上一版的真实问题

上一份《如何判断一场戏的功能》样稿收到的反馈是：重点不突出、逻辑结构不清、操作流程不具体、主次混杂、重要内容没讲透。

因此不以“覆盖了多少栏目”作为目标。应先问：读者最需要理解哪个判断？为什么难？前一个结论怎样支撑后一个行动？读到这里能否继续工作？

这条改进针对知识文章；不要把“必须六步”“必须一个反转”等做法固化成所有主题的标准。

## 2. 正文的阅读层次

以下是推荐的阅读顺序，不要求机械照用标题。根据知识类型取舍，但必须保留核心回答、必要解释和使用边界。

### 第一层：先抓住核心

开头直接回答文章问题，用简短的核心判断串起后文；指出最关键的误区、整体使用路径和最终结果。不要先讲编写背景、来源数量、版本验证或漫长概念史。

例如方法文的开头应让人知道“判断依据是什么、先做什么、结果用于什么”，而不是只说“本文很有帮助”或罗列目录。

### 第二层：讲透必要原理

围绕难点解释，而不是罗列术语定义。对核心知识回答：

- **是什么**：它解决什么具体问题，与相似概念差在哪里？
- **为什么**：条件通过什么关系产生结果？这是来源论证还是编写者解释？
- **怎样判断**：在实际输入中看什么现象或证据？不能只写抽象形容词。
- **如何取舍**：什么条件下用，何时换方法，代价是什么？

不要求每个概念四项都占一个标题；用连接清楚的文字把关键问题讲完整。来源不足以支撑机制时说明未知，不凭空补成因果定律。

**深度的判断标准**：解释是否能帮助读者分辨容易混淆的情况、处理条件变化并作出取舍。多写名词、多引用作者、多加章节，都不自动增加深度。

### 第三层：把原理转成操作

方法文先说明需要的输入、最终产物以及整体路线，再展开关键步骤。

每一步至少让读者明确：

| 要素 | 写到什么程度 |
|---|---|
| 输入 | 指明读哪部分资料、检查哪项现有结果 |
| 动作 | 具体怎样阅读、对照、记录或修改；不用“深入分析”代替 |
| 判断 | 什么证据支持哪种结论；证据不够怎么办 |
| 分支 | 不同结果分别继续、回看、补资料还是停止下结论 |
| 输出 | 留下一条什么结论或产物，怎样供下一步使用 |

不强求每步都是五列表格。简单动作一句话就够；复杂决策可以用小表或简短流程图，随后解释判断依据。

输入缺失时分开处理能继续与不能判断的部分。只有真正改变结果的重要未知才询问用户，不把每个阅读困难都转成确认关卡。

### 第四层：用同一个案例走通

给出足够输入，按正文步骤展示证据、判断、分支和最终产物。不能只在每节放一句互不相干的例子，也不能直接列“正确答案”省略关键依据。

来源案例注明范围；新编案例明确标注；真实项目遵守已确认设定。示例只帮助理解，人物背景、时长、画幅和工具不能成为默认规则。

反例聚焦容易混淆的判断：说明看起来相似但为什么应走另一分支。避免仅用显而易见的错误陪衬“正确方法”。

### 第五层：留下工作时可用的工具

流程确实需要记录时，再给精简模板或检查表。模板应与步骤输出一一对应，不能出现正文没解释的新字段，也不能要求每次填写不必要信息。

来源、阅读范围、争议和版本记录在文末。正文中的重要主张仍需就近标来源标识，防止读者无法区分依据与综合解释；不要把长篇制作日志塞进阅读主线。

## 3. 分析、整合和分类

同一主题聚合多源，但保留每种观点的条件与来源；不把“作者A这样说”和“作者B那样说”机械并排后就宣称整合完成。说明对当前问题应怎样选择，或者为什么暂时无法选择。

资料存在共识、互补、冲突或相同上游来源时分别处理。不强制凑分歧，不将所有差异抹平成共识，也不凭资料数量判定正确。

一个主题只在一个主要位置维护，相关主题通过链接关联。标题以明确问题或方法命名；不将每本书、每章、每个术语自动生成独立文章。只有相关内容具备独立使用价值才拆分。

## 4. 面向AI的可用性

AI读到一个关键段落时，应能同时知道方法、条件和限制。不要把“除非……”远远放在另一篇文档，导致只检索到无条件结论。

使用稳定名称和必要别称，标题包含真实任务词；代词应能在本节消歧。不依赖“前面聊天说过”“按旧规则”等对话外信息。

让AI能据此作判断，不意味着把所有内容改成JSON、密集指令或机械表格。知识正文仍然面向人类解释；AI执行该方法时依据的是清晰的输入、证据、决策与产物。

## 5. 输出规范

文章内简短标注版本、日期、适用范围和状态；完整阅读范围及检查记录后置。不在开头堆管理字段。输出路径遵循用户与项目约定。

来源至少包含真实文件名或链接、版本信息（若已知）、实际定位与阅读范围。PDF区别文件页序与印刷页码；DOCX结合小节、表格和短句定位。未知作者或页码不猜填。源文件变化后需要重新核对。

Markdown维护原文；按需Word导出相同版本。文章正文若重大重写，在改写前保留旧稿；不为每次标点变化建立一个新版本文件。

## 6. 写完后的实质检查

先单独读开头：能否说清核心回答、关键依据和怎么开始？

再只读各节开头和步骤输出：前后是否依赖清楚？有没有一堆同级知识点，却没有判断主线？

最后用案例实际应用：是否出现无法继续的模糊步骤、解释不了的跳跃、没有去向的分支或填写不了的字段？这些地方应改方法，不能靠增加“自行判断”推给读者。

检查不通过时采用针对性修订：

| 发现的问题 | 应怎样修订 |
|---|---|
| 重点不清 | 提炼核心判断，调整主次，删除或后置旁枝 |
| 结构不清 | 按概念依赖与工作顺序重组，不只换标题 |
| 流程抽象 | 补实际输入、判断证据、分支与输出 |
| 内容浅 | 补关键机制、难点区别与条件变化下的取舍，或补读必要来源 |
| 很深却难懂 | 减少未解释术语，用完整例子解释关键关系 |
| 案例与方法脱节 | 让同一案例按步骤走到最终产物 |
| 有来源但推断越界 | 回原文核对，缩小结论范围或明确改为候选解释 |

不把这套检查量化成未经验证的分数或“通过率”。检查者只能报告实际看到的问题与依据。
