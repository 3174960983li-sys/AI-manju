## 一、结论与适用范围

建议保留 CINEDANCE 已在使用的“素材绑定前置—全局设定—逐镜动作—统一声音”结构，吸收 prompt-builder-2-5 的模块裁剪、可观察行为和局部表达方法。重点是让每一条要求有明确归属、让摄影机与人物动作共同推进，并让站位图只承担其能表达的几何职责。

不建议将第三方的17个模块全部改成中文后搬入现有流程。CINEDANCE 已包含多数同类信息；完整拼接只会增加重复和冲突。提示词标题顺序是组织手段，当前资料不能证明某个顺序本身必然提高生成成功率。

本次交付的是优化后的通用模板，不改写《郝奶奶之月球之旅》的剧情、已确认镜头和投喂稿，不覆盖《无限杀戮》的专用六模块合同，也不修改已安装 Skill。Deepwhite v3.7 仅作为格式边界参照，其声音首行、整数秒和既定字段要求不迁入 CINEDANCE。

## 二、CINEDANCE 当前结构与逻辑

### 2.1 方法原文与实际用稿的区别

CINEDANCE V4 原文建议按“场景语境、活跃参考、场地映射、首帧、格式、光学、摄影机、动作、物理、灯光、音频、约束”组织，允许省略不需要的模块。

当前项目实例已形成更便于连续叙事的组织方式：先集中声明素材，再交代总任务、空间和视觉基线，随后按镜头执行，最后收束动态连戏与声音。它是对原方法的具体使用方式，不宜因为第三方提出另一个模块顺序而全部推翻。

### 2.2 当前使用结构

```text
素材绑定：人物、场景、道具、姿势/构图、音色分别说明用途
    ↓
整体设置与场景：发生什么、时长、画幅、镜头形式
    ↓
空间与视觉基线：地标、相对位置、材质、光源和运动质感
    ↓
逐镜：首帧 → 动作与摄影机 → 声音节点 → 衔接/结束
    ↓
动态连戏、统一声音与转场约束
```

这一结构的核心是先确定素材职责和共同世界，再安排镜头怎样观察行动。它适合有多个角色、对白、连续动作和跨镜状态的叙事段落。

### 2.3 当前实例的优点

v15 已明确区分身份参考与阶段构图参考：侧面双人关键帧只用于坐稳后的阶段，不是门口迎宾或拉椅动作的起点。它还指出场景图控制环境，逐镜机位重新组织；音频控制奶奶音色，不继承原音频台词。这些边界应继续保留。

v15 将6—12秒划为同一镜头，其中6—9秒完成落座，9—12秒询菜，明确9秒不剪切。这说明“一个时间节点”与“一个剪辑镜头”已经有区分，优化应将这一经验写得更通用，而不是重新规定所有时间段都要切镜。

在空间与动作方面，实例具体写出椅子、扶手、桌沿、双手落位和机器人通道位置；这些与剧情直接相关的执行信息，比笼统的“优雅入座”有用。

### 2.4 需要优化的地方

第一，身份、左右关系、手部、镜头数量和声音策略会同时出现在素材绑定、空间、逐镜与结尾，维护时容易漏改。应区分“素材定义”“全局基线”“当镜执行”“收尾检查”，避免四处写同一条长指令。

第二，有些镜头将人物动作、摄影机路径、焦点和结束状态合在长段里。导演阅读时能理解，但局部修订时不易定位；复杂镜头宜按几项执行内容短分句，简单镜头仍可保持自然段。

第三，首帧通常明确，落幅和跨镜继承的完整度不一。应让结束状态成为每镜收尾信息，明确下一镜接住的是动作、视线、道具还是声音，不要求额外制作另一套表格。

第四，目前能绑定构图参考，但还缺少简化站位图的通用接入约定。需要补充颜色与身份映射、参考适用阶段、站位与走位的区别，以及换机位后重新投影的规则。

## 三、prompt-builder-2-5 的结构与逻辑

### 3.1 它怎样组织提示词

该包内部名称是 `seedance-clean`，正文标题为 Seedance 2.5 Prompt Writer。它要求输出一份独立英文提示词，并放在代码块中。主模板列出17个模块，注明按实际需要删减：

```text
场景语境 → 有效参考 → 空间映射 → 首帧站位 → 镜头形式
→ 光学 → 摄影机 → 动作 → 表演 → 物理
→ 灯光 → 调色 → 服装 → 声音 → 风格 → 输出设置 → 正向锁定
```

它希望把内容拆成有明确职责的块：角色图控制外貌，文字控制行动；光线写在灯光中，表演写在表演中，技术设置放到末尾。这样容易定位和修改，也便于省略不重要的模块。

### 3.2 可吸收的方法

**描述可见、可听的事情。** 情绪通过选择、动作与反应落实。微表情是可用手段，但不把每种情绪都固定为吞咽、握拳或红眼。

**生成单元可以独立理解。** 每条写清当前人物、空间、动作和必要声音，不依赖模型记得上一条。跨段状态应转写为本段事实，不能只写“接上段”。

**根据任务选择控制精度。** 一镜到底、顺序切镜、严格时间切镜和自由素材镜头的需求不同，不应一律使用大量小数时间码。

**风格落到对应内容。** 用材质和受光描述画面，用表演行为描述情绪，减少无具体作用的形容词。整体媒介和风格仍可简洁放在全局基线中。

### 3.3 不吸收的规则及原因

| 原文规则或说法 | 问题 | 优化处理 |
|---|---|---|
| 只允许正向表达 | 自己使用了多个否定句，也缺少“任何否定都无效”的证据 | 目标正向描述为主；关键失败允许简短、局部、明确的禁止 |
| CAMERA 必须位于第三层 | 主模板中位于第七个模块，且 ACTION 在后 | 将摄影机紧邻对应镜头行动，不声称排序保证效果 |
| 所有速度使用 km/h | 摇摄属于转动，“5 km/h 摇摄”不能说明转动过程 | 根据运动选用方向、位移/角度、耗时和可见起止 |
| 雾密度写百分比 | 没有基准，难以复现或验收 | 用遮挡距离、主体清晰度、轮廓层次描述 |
| 视角只能从固定表中选 | 未交代视角方向和画幅条件，无需排斥其他角度 | 优先景别与空间效果；必要时标焦距观感或有依据的FOV |
| 摄影机总在阴影侧 | 属于可选造型方法，不适合所有场景 | 依据人物、空间和光线意图选择 |
| 固定0.8秒甩镜阈值、四重协议 | 没有随包提供实验条件和对照证据 | 作为有条件的经验候选，不写入通用硬要求 |
| 图像角色卡可锁定跨片声音 | 没有提供足以支撑保证的验证 | 单独描述声音身份；有音色资料则绑定并实际核验 |
| 每个镜头增加雾气 | 无剧情依据会引入环境变化 | 环境状态按真实因果延续 |
| 2分钟等于四次生成 | 只是理想时长相加，没有重试和剪辑余量 | 区分叙事镜头、生成任务和实际尝试次数 |

其“2.5只输出720p”的表述还存在时效和模式问题。2026-10-25核对的 Higgsfield 2.5 文生视频接口列出4—30秒、480p/720p/1080p；帮助页另将2.5 Edit列为480p—720p。参数应按平台、端点/模式及当时界面核对，而不是写成全平台永久规则。[官方接口](https://open.higgsfield.ai/models/bytedance/seedance-2.5/text-to-video/api-reference) · [官方使用说明](https://higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-use-seedance)

## 四、逐项对比与选择

| 比较项 | 当前 CINEDANCE | prompt-builder-2-5 | 本次采用 |
|---|---|---|---|
| 素材位置 | 素材绑定前置 | 场景语境后列参考 | 保留素材前置，便于核对职责 |
| 风格组织 | 全局风格/材质光线＋逐镜执行 | 风格分布到各块，技术设置后置 | 全局只写共同基线，局部只写变化 |
| 空间 | 世界地标、人物关系、逐镜机位 | 前中后景＋首帧站位 | 加强世界空间与当前画面投影的区别 |
| 镜头组织 | 实例中逐镜展开 | 主题模块分列，允许多段 | 保留逐镜，让动作与摄影机就近对应 |
| 表演 | 行动、情绪与动作时间轴 | 肌肉动作与微反应 | 行动选择优先，微反应适量使用 |
| 时间精度 | 按剧情非等分，必要时小数 | 顺序切镜或精确时间等多种 | 设计阶段可用事件；正式版按需求定精度 |
| 摄影机 | 与构图、动作、空间结合 | 单列光学与摄影机模块 | 每镜明确起点、触发、路径、落点 |
| 物理 | 接触、重量、环境反馈 | 独立 PHYSICS 模块 | 无复杂物理时并入动作，不额外填块 |
| 声音 | 实例同时有逐镜声音与结尾总结 | 集中 AUDIO | 台词原文集中一次，镜内标动作同步与声画关系 |
| 结尾 | 逐镜结束及全段连戏约束 | 关键锁定为主 | 明确末态与下一单元入口 |
| 语言 | 中文 | 固定英文 | 通用模板用中文；按平台/用户需要再编译语言 |
| 检查 | 空间、时间、素材、物理和剧情 | 字段、标签、固定参数清单 | 检查内容成立，不以字段填满代替质量 |

### 4.1 优化后的六个编写区块

```text
素材绑定与使用边界
    ↓
生成目标与拍摄形式
    ↓
空间与全局视觉基线
    ↓
逐镜执行／一镜到底路径节点
    ↓
统一声音与对白
    ↓
结尾状态与必要约束
```

这里的“六个区块”只用于 CINEDANCE 通用模板的阅读组织，和《无限杀戮》的六模块合同不是同一套格式。它们不强制每项都单列；无素材、无对白或简单单镜头时允许合并省略，不能留下空占位。

### 4.2 全局与局部的分工

素材段定义引用职责，不能提前冻结后续全部动作。全局段定义不随镜头变化的世界和视觉基线。逐镜段写本镜可见对象、当前投影、动作与摄影机过程，只补本镜变化。声音段集中写台词原文、说话人、音色和声桥。结尾只写落点与高风险约束，不重抄所有前文。

遇到真实冲突时停止依赖冲突的部分，先核对用户锁定内容与实际素材。当前文字允许的状态变化可以覆盖参考图中的旧姿态；角色身份、站位、声音分别按已声明职责引用。不能靠简单规定“文字永远压过图像”来承诺模型会正确执行。

### 4.3 同一内容怎样由长段改成可维护的执行描述

下面是虚构片段，只演示组织方式，不代表现有用稿必然存在同样问题。

原始合写：“甲在左边把信封放到桌上，乙在右边看着她，镜头慢推，西窗光很柔和，甲转身离开，乙拿起信封，结尾停在乙脸上，人物和信封保持一致。”

这句话交代了事件，却没有说清甲的退场是否挡住摄影机、乙何时开始拿信、镜头怎样从两人变成乙的近景。

优化后的分工是：空间基线只写“甲在桌南侧，乙在桌北侧，窗在西墙”；镜头起幅写清摄影机位于桌东侧、两人和桌面信封均可见；动作写“甲放下信封并松手，向南退场，乙待甲的手离开后伸手拿起”；摄影机写“先保持双人中景，甲退场后沿桌东侧向乙推进，焦点从信封转至乙的眼睛”；落幅写“乙右手拿着信封，视线从封口抬向甲离开的方向”。

变化来自补足执行关系，并非多加几个标题就能提升效果。具体站位、运镜和节拍仍应来自当前导演方案，不能把示例变成固定套路。

## 五、角色站位图的接入方式

### 5.1 存放与来源

用户指定保存目录：`E:\AI漫剧\02_制作方法\02_专业技能\自研Skill\tig-blocking-map`。虽然位于自研Skill分类，本包仍为用户提供的第三方方法，不改署名，不标为自主创作。

包内 `SKILL.md` 按原字节保存；原始 `.skill` 包放在同目录的 `原始附件` 中。当前按完整路径可读取使用，未因归档而自动安装到 Codex 全局目录。

### 5.2 什么情况下使用

多人朝向、跪坐姿势、局部裁切、持物高度、前后遮挡或关键接触容易混淆时使用。简单单人镜头和清晰的现成关键帧，不强制额外画图。

区分三种图：俯视调度图帮助设计世界位置、行动轴和摄影机；画面站位图帮助表达某个机位看到的构图；成片关键帧承担实际外观与最终视觉。TIG主要属于第二种，不能单靠它解决三维空间与完整动态。

### 5.3 实际顺序

1. 从已确认文字或用户指定画面明确构图、裁切、位置、朝向、道具高度与可见范围。
2. 编写站位图提示词；只有用户需要实际图片时才生成。
3. 实际查看返回图，修正错位、漏人、补全裁切身体等问题；关键错误不以“文字会覆盖”为由放行。
4. 建立颜色—角色—实际参考的对应，说明该图控制哪个镜头或哪个阶段。
5. 编写视频提示词：身份、服装来自角色资料；环境来自场景资料；站位图只提供当前几何关系。
6. 有换机位时，按同一世界关系重新推导画面；必要时做另一个机位的站位图。

“位置参考”不等于全程静止。只约束指定起始阶段，人物按正文的走位离开起始点。原图的蓝色轮廓不代表蓝色衣服，图上箭头也不是成片特效。

### 5.4 素材引用与工具边界

TIG的 `@staging_...` 和 `@loc_...` 是方法命名，不能据此认定平台已建立引用。真正投喂时须核对上传槽位或可点击引用；A、B等字母也只是文字别名，不能凭空创建有效平台资产。

原包要求站位图最后附加，且图像模板含特定工具参数。这些保留在原文中便于追溯；使用时按实际工具适配，不把上传顺序当可靠保证，也不把 `--v` 等参数直接塞给不支持的工具。

## 六、怎样验证这次优化

文字检查只能证明引用、职责和逻辑较清楚，不能证明成片更稳定。以下是后续可选的验证设计，本次未提交付费生成。

| 验证对象 | 比较方案 | 主要观察 |
|---|---|---|
| 提示词结构 | 原CINEDANCE vs 优化结构；其余输入尽量一致 | 剧情覆盖、动作完整、摄影机执行、首尾状态、对白 |
| 站位图辅助 | 同一优化提示词，有图 vs 无图 | 身份映射、相对位置、朝向、接触点、图形风格污染 |
| 跨镜连续性 | 同一场景的换机位和动作承接 | 世界位置、道具手位、光向、视线与动势 |

先把“结构是否有帮助”和“站位图是否有帮助”分成两组比较，避免同时改动后不知道改善来自哪里。支持固定种子时尽量固定；不支持时记录样本差异和尝试次数，不用一条成功结果推断稳定成功率。

验收先看不可丢失的剧情与对白，再看身份、空间、接触和镜头任务，最后看风格。记录输入版本、实际引用、模型模式、平台设置、输出和具体缺陷。没有依据不设“至少四批才换方案”的固定消耗。
