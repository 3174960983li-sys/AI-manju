# 双路线AI叙事制作体系 架构设计主提示词

版本：V1.0｜日期：2026-10-24。用途：可复制给AI助手，用于设计或持续完善双路线体系。它是任务提示词，不是已经部署的Agent或Skill。

## 可直接复制的主提示词

```text
请担任我的AI叙事视频制作体系架构师与方法研发负责人，基于现有项目资料，设计可实施、可验证、可逐步迭代的双路线制作体系。

一、建设目标
建立两套可独立使用的完整基础体系：
1. 3D漫剧/3D动画叙事视频。
2. AI仿真人叙事视频。
两套体系均以漫剧/短剧为核心、兼容剧情短片，覆盖创意或原著开发、系列与剧本、导演视听、视觉与资产、单场与分镜、视频提示词与真实生成、声音与后期、质量检查、交付归档和复盘迭代。
每套都需要完整SOP、对应总控Agent职责，以及可调用的阶段Skill组合。Agent先落实为Codex中的职责、输入输出、交接和方法选择，不预设多Agent自动调度平台。

二、架构要求
采用共同基础、双制作路线、专业扩展、项目实例和经验版本库分层。共同基础统一对象和交接，但两条路线必须落实真实专业差异，不能仅替换标题。共享规则保持一个维护源，两套完整SOP明确引用版本。
将题材、视觉传统、表现方式、制作形态和实现方法作为可组合维度。例如国漫取向、仙侠题材、适度写实CG和竖屏连载可以组合，不为每个组合复制整套SOP。只有反复出现实质方法差异时，才提炼独立专业Agent或Skill。
3D路线不强制传统建模、绑定、动画、渲染全套流程；按实际任务选纯AI或三维辅助等实现方法。仿真人路线须对身份、自然表演、皮肤衣料、手部口型及实感光源等建立专业方法。

三、职责边界
SOP负责流程与完成标准；Agent负责判断、路由、交接和冲突处理；Skill负责专业执行方法；项目配置负责具体作品事实和风格；工具适配负责实际平台输入输出。
每个阶段明确必要输入、执行步骤、交付、检查、返工和下一接收方。创作、审查、实际生成和部署分别辨认，不以文稿完成替代真实媒体通过。
复用适用的现有Skill，先映射再补缺口。同一工作单元确定一个主流程；不要叠加多套输出格式，不批量覆盖现行Skill或已有作品默认约定。

四、资料与迭代要求
原资料、候选方案、用户采用和实测证据分别记录。具体作品的角色、剧情、图号、资产与版本独立；跨项目只迁移方法及适用条件。
从真实问题定位最早责任层，修最小范围。项目问题优先留在项目，风格/题材方法回专项，路线问题回对应基础，跨路线共通问题才回共同层。保留反例、失效条件和旧版本，不把单次成功升为普遍定律。
文本完整、角色职责清楚、Skill能够调用、真实链路跑通、稳定复用分别设完成标准；未验证时如实说明。既有CG案例不能替代仿真人路线验证。

五、工作方式与交付
先准确复述需求和关键边界。优先查已有资料；只有实质改变方案的缺失信息或个性化方向才询问我，其余合理推进。
交付专业架构图、两路线差异表、全流程阶段与交付表、Agent职责与交接表、Skill复用/新增判据、项目配置机制、版本迭代规则及按依赖排序的任务包。不要为了完整而穷举风格、创建空目录或自动系统。
资料统一根目录为E:\AI漫剧，遵守现有作品的归档约定。按任务包推进，不排固定周计划。当前只交付设计及明确要求的文稿；安装、修改现行Skill、新媒体生成、迁移删除、对外发布等依据后续实际授权执行，不能从本提示词推定授权。
```

## 后续启动具体项目时的补充提示词

```text
请依据已确认的双路线SOP与角色职责，为本项目建立专业化制作配置。
先查项目现有资料并确定有效版本，再明确制作路线、题材、视觉传统、表现方式、叙事形态、风格参考、交付规格和工具条件。只询问会实质影响方案且资料无法查明的信息。
输出该项目采用的SOP版本、角色与Skill组合、相对通用基础的具体差异、保留项、专业扩展需求及首个任务包。已有配置足够时不要新建一整套Skill；确有可复用独特方法时再提出专业Skill设计。
不得把其他作品的设定、素材编号或生成结果混入本项目。当前未明确的内容标候选或待确认，待采用范围清楚后再执行相应制作。
```
