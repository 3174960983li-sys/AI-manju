# 怎样让Skill提供稳定的专业帮助

版本V0.1｜2026-10-30｜状态：有来源的研究提炼，制作效果待具体任务验证。

Skill应当保存可复用的方法，而不是把所有知识和所有项目设定堆进一份长指令。优秀的结构能降低误触发和上下文负担，但真正有用仍要由任务结果证明。

<a id="G06"></a>
## G06 · 一个Skill围绕一个完整职责

以连贯任务为单位组织Skill，避免过宽或碎得无法独立使用。 过宽容易误触发，过碎会要求同时加载多个重复模块。

**本项目用法：**写清何时使用、不负责什么、输入输出；相同方法集中维护一次。

**教学示例：视频结果审查与视频提示词编写可以分责，共用连续性知识，不复制两份定义。**

**适用边界：**职责不等于固定职业头衔；用户一次任务可以顺序调用多个职责。

**检查办法：**检查一个典型请求能否明确选择主Skill并按目标交付。

来源：[S01](来源与阅读边界.md#S01)、[S02](来源与阅读边界.md#S02)、[S09](来源与阅读边界.md#S09)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G07"></a>
## G07 · 正文保留主流程，细节按条件读取

主文件描述判断与步骤，参考资料承担复杂规则和示例。 长正文会把不相关的规则带进简单任务。

**本项目用法：**每个参考入口写明触发条件，而非只写“详见references”；共享知识从唯一原件引用。

**教学示例：只在跨段续作时读取状态交接说明；只在生成失败时读取诊断表。**

**适用边界：**不要为追求短文件拆得过细，必要检查应留在主流程。

**检查办法：**用不同任务检查实际读取内容是否相关、是否遗漏必需定义。

来源：[S01](来源与阅读边界.md#S01)、[S02](来源与阅读边界.md#S02)、[S13](来源与阅读边界.md#S13)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G08"></a>
## G08 · 规则来自真实纠错与专业证据

记录用户为什么纠正一次结果，再提取可迁移的方法。 笼统的“遵循最佳实践”无法告诉Agent怎样避免同类错误。

**本项目用法：**保存失败输入、错误输出、纠正动作、适用范围；把实例中的项目名和素材号参数化。

**教学示例：一次左右手错误可转化为持有者/手别检查，不把该作品永远左手持物写入通用Skill。**

**适用边界：**单次成功只构成候选经验，不能保证跨模型有效。

**检查办法：**新规则能对应至少一个真实或明确标注的教学反例。

来源：[S02](来源与阅读边界.md#S02)、[S04](来源与阅读边界.md#S04)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G09"></a>
## G09 · 精确约束与创作自由分别配置

容易造成交接错误的字段严格约束，创作选择解释目的和判断标准。 统一强硬规则会把审美偏好变成无必要限制。

**本项目用法：**素材编号、字段和授权严格检查；景别、节奏、表演幅度按叙事判断。

**教学示例：素材ID必须准确；镜头是否采用近景，依据本镜信息任务而非固定比例。**

**适用边界：**特定平台或用户确有格式要求时保留硬约束。

**检查办法：**评审每条强制句：是接口要求、已确认事实，还是作者偏好？

来源：[S02](来源与阅读边界.md#S02)、[S09](来源与阅读边界.md#S09)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G10"></a>
## G10 · 格式、触发与输出效果分别验收

Skill结构合规，只能证明能被正确读取，不证明会被正确调用或能产生好结果。 一个写得规范但误触发的Skill仍会扩大任务范围。

**本项目用法：**分别检查元数据与引用、应该/不应该触发的请求、实际输出和成本；改版保留对照。

**教学示例：用户问“点评这段分镜”应进入审查，而非自动调用生成图片。**

**适用边界：**触发评测不能替代专业效果评测；模型升级可能改变表现。

**检查办法：**记录误触发、漏触发及合格交付率，避免只有文件格式通过。

来源：[S01](来源与阅读边界.md#S01)、[S04](来源与阅读边界.md#S04)、[S17](来源与阅读边界.md#S17)。用法与示例为本项目综合改编，不是已验证结果。
