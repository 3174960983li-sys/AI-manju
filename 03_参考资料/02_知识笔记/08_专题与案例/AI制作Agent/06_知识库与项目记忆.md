# 怎样积累知识而不混淆事实

版本V0.1｜2026-10-30｜状态：有来源的研究提炼，制作效果待具体任务验证。

阅读资料不会自动让系统永久掌握全部内容。可维护的成果应是带来源的知识、适用范围、项目事实与运行记录。把它们混放在聊天摘要里，容易产生跨项目误用、旧版本污染和来源丢失。

<a id="G26"></a>
## G26 · 通用知识、项目事实和运行进度分开

知识说明方法，项目事实描述作品，运行进度记录本次任务。 一个作品的角色状态如果变成通用记忆，会污染其他作品；运行失败也不等于方法无效。

**本项目用法：**分别存放专业知识、已确认设定与任务状态，检索时限定项目和版本。

**教学示例：连续性检查是通用方法；甲在第三场受伤是作品事实；第三场视频仍下载中是进度。**

**适用边界：**小项目可用不同文件段落，不必一开始上复杂数据库。

**检查办法：**随机跨两个项目提问，来源和设定不会串用。

来源：[S27](来源与阅读边界.md#S27)、[S28](来源与阅读边界.md#S28)、[S19](来源与阅读边界.md#S19)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G27"></a>
## G27 · 记忆摘要必须回指原文

摘要帮助定位，不替代已确认剧本与资产。 省略知情差异、否定语句或未兑现伏笔，会改变剧情逻辑。

**本项目用法：**记忆条目带原文位置、版本、事实/推断标签；关键改编前回查原文。

**教学示例：摘要只写“乙拿到钥匙”，原文可能是甲以为乙拿到；人物与观众知情必须分开。**

**适用边界：**这是对逐集记忆方案的保真增强建议；原代码并未自动证明摘要正确。

**检查办法：**针对人物知情、道具持有与未兑现事件建立人工对照。

来源：[S22](来源与阅读边界.md#S22)、[S27](来源与阅读边界.md#S27)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G28"></a>
## G28 · 长度截断不能冒充知识压缩

丢弃旧条目与保留语义的压缩是两件事。 Novel2Drama的读取代码按最近集数累加，超限后停止，早期内容可能完全不进入上下文。

**本项目用法：**单独保留未解决事件与稳定设定索引；缩短摘要时记录丢失内容，不宣称仍保有全部信息。

**教学示例：第一集埋下的匿名信在第十集才兑现，不能因第一集较旧就从相关上下文移除。**

**适用边界：**本条来自静态代码检查，不代表运行测试；按最近优先仍适合不需要早期事实的任务。

**检查办法：**用跨多集回收伏笔的材料，检查是否能找到早期依据。

来源：[S22](来源与阅读边界.md#S22)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G29"></a>
## G29 · 知识检索要同时看找全与找准

找到相关资料并不足够，还要避免把无关或旧版内容一起送给Agent。 过多噪声会压过关键限制；遗漏则导致无依据推断。

**本项目用法：**为典型问题列出应命中与不应命中的资料，检查检索结果及回答是否受来源支持。

**教学示例：查询某项目当前分镜格式，应命中该项目有效约定，不以其他作品模板替代。**

**适用边界：**LightRAG样例分数不作为本库统一阈值；尚未需要RAG时先用目录与关键词索引。

**检查办法：**记录遗漏、误命中和无来源回答，而非只看答案顺不顺。

来源：[S26](来源与阅读边界.md#S26)、[S28](来源与阅读边界.md#S28)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G30"></a>
## G30 · 经验晋级必须带证据和边界

候选经验通过具体任务验证后，才能成为限定范围的操作建议。 把作者宣传或一次幸运结果固化，会让系统反复执行脆弱规则。

**本项目用法：**经验卡记录输入、模型版本、方法、对照、结果和失败情况；规则升级保留适用条件。

**教学示例：某镜头补出口状态后改善，先记该模型与动作范围，再用其他动作检查迁移性。**

**适用边界：**这是一种维护建议，不自动写入全局记忆，也不把所有经验变成硬标准。

**检查办法：**任何“已验证”条目都能打开对应输入和输出证据。

来源：[S02](来源与阅读边界.md#S02)、[S03](来源与阅读边界.md#S03)、[S06](来源与阅读边界.md#S06)。用法与示例为本项目综合改编，不是已验证结果。
