## 怎样使用

先找当前问题，只读取所需章节。每条知识包含原理、本项目用法、教学示例、适用边界和检查办法；例子不是源作者的真实实验，也不是本项目已验证结果。

本轮区分三种内容：来源明确陈述的规范或实现；由来源综合的候选方法；需要目标模型实测的效果假设。不能把中文整理完成等同于行业标准或生产验收通过。

## 40条知识速查

| ID | 主题知识 | 用途 |
|---|---|---|
| G01 | [按交付结果划分节点](01_SOP节点与交接.md#G01) | SOP的节点以能够检查的成果结束，而不是以“调用了某个模型”结束。 |
| G02 | [输入需要版本和权威来源](01_SOP节点与交接.md#G02) | 输入不仅是一条文件路径，还包括有效版本、确认状态和适用项目。 |
| G03 | [用条件而不是固定仪式控制流程](01_SOP节点与交接.md#G03) | 前置条件满足即可进入节点；只有真实缺口才等待补充。 |
| G04 | [返工指向最早有证据的错误](01_SOP节点与交接.md#G04) | 发现视频问题后，先区分剧本、分镜、参考图、提示词、工具与后期问题。 |
| G05 | [上游变更要检查下游影响](01_SOP节点与交接.md#G05) | 已确认设定变更后，只重查受影响成果，并保留旧结果对应关系。 |
| G06 | [一个Skill围绕一个完整职责](02_Skill设计与维护.md#G06) | 以连贯任务为单位组织Skill，避免过宽或碎得无法独立使用。 |
| G07 | [正文保留主流程，细节按条件读取](02_Skill设计与维护.md#G07) | 主文件描述判断与步骤，参考资料承担复杂规则和示例。 |
| G08 | [规则来自真实纠错与专业证据](02_Skill设计与维护.md#G08) | 记录用户为什么纠正一次结果，再提取可迁移的方法。 |
| G09 | [精确约束与创作自由分别配置](02_Skill设计与维护.md#G09) | 容易造成交接错误的字段严格约束，创作选择解释目的和判断标准。 |
| G10 | [格式、触发与输出效果分别验收](02_Skill设计与维护.md#G10) | Skill结构合规，只能证明能被正确读取，不证明会被正确调用或能产生好结果。 |
| G11 | [稳定身份与剧情状态分开](03_导演连续性与素材绑定.md#G11) | 角色身份、道具设计等相对稳定；湿润、受伤、持物和位置随剧情变化。 |
| G12 | [记录动作入口、变化与出口](03_导演连续性与素材绑定.md#G12) | 动作描述需要说明开始时是什么状态、发生什么、最后停在哪里。 |
| G13 | [把空间关系转成可观察信息](03_导演连续性与素材绑定.md#G13) | 位置、身体朝向、视线目标、运动方向与环境锚点要相互一致。 |
| G14 | [每份参考都写明用途与版本](03_导演连续性与素材绑定.md#G14) | 身份图、场景结构图、首帧、运动参考和音色参考承担不同作用。 |
| G15 | [镜头、叙事节拍与生成片段是不同单位](03_导演连续性与素材绑定.md#G15) | 镜头是观看组织，节拍是信息或行动变化，生成片段是工具执行容器。 |
| G16 | [生成前、片段后、序列后三层检查](04_质量检查与返工.md#G16) | 输入可执行性、单段质量和连续剪辑效果应分别检查。 |
| G17 | [关键缺陷与评分分开](04_质量检查与返工.md#G17) | 明确必须修复的问题，再使用评分比较其余质量差异。 |
| G18 | [问题描述要有时间位置和预期](04_质量检查与返工.md#G18) | 用可定位症状取代“不自然”“不够高级”。 |
| G19 | [先选最低成本的有效修正](04_质量检查与返工.md#G19) | 根据原因决定改描述、换参考、拆动作、补镜还是后期修整。 |
| G20 | [自动视频指标只覆盖部分质量](04_质量检查与返工.md#G20) | 将人体、身份、服装、空间和运动等维度分别考察，再补人类剧情判断。 |
| G21 | [运行状态要有明确证据](05_Agent运行与故障恢复.md#G21) | 等待、运行、成功、失败、取消和受理不明需要分别表示。 |
| G22 | [受理结果未知时不能盲目重提](05_Agent运行与故障恢复.md#G22) | 网络超时不等于服务端没有接受请求。 |
| G23 | [检查点与任务事实分别保存](05_Agent运行与故障恢复.md#G23) | 检查点保存流程执行位置，外部任务记录保存实际提交与结果。 |
| G24 | [原始错误与用户解释分开](05_Agent运行与故障恢复.md#G24) | 保留工具原始错误信息，再给用户可理解的说明。 |
| G25 | [生成和查询由清晰的工具合同连接](05_Agent运行与故障恢复.md#G25) | 工具需要明确输入、返回值、错误与完成条件，而不是只提供一段操作说明。 |
| G26 | [通用知识、项目事实和运行进度分开](06_知识库与项目记忆.md#G26) | 知识说明方法，项目事实描述作品，运行进度记录本次任务。 |
| G27 | [记忆摘要必须回指原文](06_知识库与项目记忆.md#G27) | 摘要帮助定位，不替代已确认剧本与资产。 |
| G28 | [长度截断不能冒充知识压缩](06_知识库与项目记忆.md#G28) | 丢弃旧条目与保留语义的压缩是两件事。 |
| G29 | [知识检索要同时看找全与找准](06_知识库与项目记忆.md#G29) | 找到相关资料并不足够，还要避免把无关或旧版内容一起送给Agent。 |
| G30 | [经验晋级必须带证据和边界](06_知识库与项目记忆.md#G30) | 候选经验通过具体任务验证后，才能成为限定范围的操作建议。 |
| G31 | [新旧版本使用相同输入与环境](07_评测与版本迭代.md#G31) | 控制任务、素材、模型配置和输出要求，再比较方法差异。 |
| G32 | [评测覆盖边界和误触发](07_评测与版本迭代.md#G32) | 正常任务、信息缺失、范围受限和冲突输入需要一起测。 |
| G33 | [机械检查与专业判断分工](07_评测与版本迭代.md#G33) | 字段完整、文件存在等适合自动检查；因果、表演和美感需要专业审阅。 |
| G34 | [合格率要结合成本与人工返工](07_评测与版本迭代.md#G34) | 方法价值同时体现在质量、费用、耗时与人工修改量。 |
| G35 | [更新需要回归与回退依据](07_评测与版本迭代.md#G35) | 新规则修复当前问题后，还要检查是否破坏已能完成的任务。 |

| G37 | [声音按持续关系组织](08_剪辑声音与交付数据.md#G37) | 对白、动作声、环境声与音乐各自有开始、持续和结束。 |

## 后续维护

新增证据写回对应条目的适用条件与结果记录，不为每次使用复制新知识包。模型能力、格式限制和费用在实际实施时重新核对；本轮没有修改全局规则或持久记忆。
