# 可借鉴知识与规则冲突

以下是对已读取材料的中文归纳。可借鉴点与本项目建议分开理解，尚未自动写入现有SOP或Skill。

## 值得吸收的知识点

| 知识点 | 来源 | 建议转化方式 |
|---|---|---|
| Skill应补充模型容易做错的具体知识，而非重复通用常识 | [agentskills最佳实践](项目卡片/agentskills__agentskills.md) | 每条规则回答：不写这一条，哪个真实任务会失败？ |
| 大型Skill按任务加载参考资料 | [agentskills](项目卡片/agentskills__agentskills.md)、[DirectorSKILL](项目卡片/wuwangzhang1216__DirectorSKILL.md) | 主文件保留用途与路由，专业细节放reference，不每次全量加载 |
| 同一任务需要基线对照 | [Skill评测](项目卡片/agentskills__agentskills.md)、[Promptfoo](项目卡片/promptfoo__promptfoo.md) | 同题比较无Skill/有Skill或旧版/新版，并保留失败结果 |
| 验收项应能提供证据 | [Superpowers](项目卡片/obra__superpowers.md) | 文本以具体字段和内容依据检查，文件以实际产物检查，视频以观看和测量检查 |
| 需求、执行计划、验收应分开表达 | [Spec Kit](项目卡片/github__spec-kit.md) | 一个节点分别记录要什么、怎么做、如何认定完成 |
| 状态连续性必须跨镜保存 | [DirectorSKILL](项目卡片/wuwangzhang1216__DirectorSKILL.md)、[waoowaoo](项目卡片/waooAI__waoowaoo.md) | 人物、道具、位置、视线、光线、已完成动作和声音分别记录 |
| 素材身份与素材用途不同 | [waoowaoo](项目卡片/waooAI__waoowaoo.md) | 参考图用于身份、场景或首帧时明确区分；绑定到真实版本和槽位 |
| 失败先保留原始证据，再决定是否重试 | [waoowaoo失败治理](项目卡片/waooAI__waoowaoo.md) | 保存错误、请求ID和执行状态；能否重复执行取决于副作用与幂等约定 |
| 提示词问题与上游设计问题要分开 | [DirectorSKILL失败手册](项目卡片/wuwangzhang1216__DirectorSKILL.md) | 建立症状→候选原因→最低成本修正→复验结果记录 |
| 视频检查至少分三个阶段 | [DirectorSKILL QC](项目卡片/wuwangzhang1216__DirectorSKILL.md) | 生成前检查输入；生成后检查片段；剪辑后检查序列连续性 |
| 视频质量可以拆维度 | [VBench](项目卡片/Vchitect__VBench.md) | 将身份、衣着、人体、物理与空间问题分开评价，再由人判断剧情表演 |
| 记忆快照与事实权威不同 | [Novel2Drama](项目卡片/Wsal4__novel2drama.md)、[Microsoft课程](项目卡片/microsoft__ai-agents-for-beginners.md) | 记忆回指原剧本版本；推断与已确认设定分开，旧伏笔不能仅按新近程度丢弃 |
| 运行检查点与知识库是两种信息 | [LangGraph](项目卡片/langchain-ai__langgraph.md) | 任务做到哪一步放运行状态，专业经验放知识库 |
| 剪辑计划需要结构化时间与媒体引用 | [OpenTimelineIO](项目卡片/AcademySoftwareFoundation__OpenTimelineIO.md) | 交接清单记录素材、入出点、帧率、轨道与时长，不仅写剪辑描述 |

## 不能直接照搬的规则

| 外部规则或宣称 | 问题 | 本项目采用建议 |
|---|---|---|
| 单次视频必须吃满15秒 | [中文SOP](项目卡片/ShuaiMXu__ai-comic-production-sop.md)的作者策略；混淆生成片段与镜头，模型限制也会变 | 按动作复杂度、叙事节奏、平台能力与成本选择长度 |
| 每个转场都要过渡帧或叠化 | 同一SOP偏创意音乐视频；常规场景并不都需效果转场 | 让转场服务叙事，保留直接切换与动作匹配 |
| 脸部镜头固定3–5秒、三次失败必须采取某动作 | [DirectorSKILL](项目卡片/wuwangzhang1216__DirectorSKILL.md)的启发式，缺少针对本项目模型的实验 | 作为初始试验策略，记录模型版本与失败类型后再校准 |
| 一律特写≥40%、台词≤15字、每30秒一个冲突 | [Novel2Drama](项目卡片/Wsal4__novel2drama.md)模板化偏好 | 用题材与剧情判断，不能当专业通用标准 |
| 每一步都要求用户手动输入菜单或确认 | [短剧提示词套件](项目卡片/yuanhongchen56-web__short-drama-ai-filmmaking.md)的交互设计 | 自动化只在真实信息缺失、关键创作取舍和授权边界处等待 |
| 提示词等于算力分配；越靠前必然权重越高 | 同套件中的机制解释没有足够证据 | 将清晰、具体、重点前置视为待检验写法，不宣称固定底层机制 |
| “官方Prompt手册”意味着平台官方标准 | [中文SOP的CREDITS](https://raw.githubusercontent.com/ShuaiMXu/ai-comic-production-sop/aef5ed714e987f8ac82d55d28582f3b909f5b877/CREDITS.md)显示经第三方资料二次提炼 | 保留完整来源链；未核平台原文前标为社区整理 |
| README提供桌面客户端就能直接使用 | 短剧提示词仓库当前文件树不含其宣称的app.py | 按实际文件判定，本轮只收录提示词参考 |
| VBench2所有18维都能直接评价任意自定义成片 | 当前README的自定义视频段落只列5种支持维度 | 按具体评测器要求确认输入，不替代剧情审美验收 |
| 根目录许可可以覆盖全仓 | Anthropic按Skill、Langfuse按ee目录、VideoAgent按第三方组件存在差异 | 复用具体文件前记录该文件适用许可 |

## 建议的经验卡字段

以下是依据上述来源综合提出的本项目候选模板，不是外部仓库原文，也未升级为全局规则。

```text
经验名称：
适用节点／项目／工具与模型版本：
遇到的问题与可见证据：
输入条件与素材：
采取的方法：
对照方法：
实际结果与失败例：
费用／耗时／尝试次数：
不适用条件：
证据文件与原始来源：
验证状态：候选／已在某范围验证／待复核
```

单次成功先记为候选经验。新增经验先用代表性任务检查，再决定是否写入节点标准或Skill。
