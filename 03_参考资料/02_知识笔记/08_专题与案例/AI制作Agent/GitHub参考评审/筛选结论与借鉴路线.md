# 筛选结论与借鉴路线

用途：从搜集结果中选出适合AI漫剧/仿真人制作Agent的材料。状态：研究建议，未成为正式项目规则。

## 核心结论

本轮找到不少可用的局部方法，但没有验证到一套可以原样接入、覆盖你的全部制作环节且稳定自动运行的成品。建议组合“影视专业方法 + 节点与Skill规范 + 运行机制 + 分层质量检查”。不要同时安装所有框架，也不要合并所有强制规则。

这里的优质是指文档结构具体、来源可追溯、与目标有明确对应关系，不表示已经通过本机运行、制作效果或安全审计。

| [Spec Kit](项目卡片/github__spec-kit.md) | 需求、计划和检查表分离 | 将SOP节点变成清晰的输入输出与验收合同 |

## 与建设节点的对应关系

| 建设节点 | 主参考 | 建议本地化产物 | 最小验证方式 |
|---|---|---|---|
| 任务接收与范围 | Spec Kit | 任务卡：目标、输入、输出、限制、未知项 | 同一材料分别要求分析、修改、生成，确认不会扩大范围 |
| 小说/剧本到分集 | Novel2Drama | 分集大纲与人物状态结构 | 对照原文核查人物知情与事件顺序，人工确认改编范围 |
| 导演与分镜 | DirectorSKILL | 镜头叙事任务、站位、动作起止、连续性表 | 用一场双人对话与一场连续动作检查空间和因果 |
| 资产与素材绑定 | DirectorSKILL、waoowaoo | 资产身份与可变状态分离，素材角色、版本、槽位表 | 故意换错参考图，确认检查能发现 |
| 图片与视频生成 | ComfyUI、waoowaoo | 工具输入输出、任务ID、预算、返回文件 | 先做无费用的接口与状态模拟，再单独安排真实生成验证 |
| 文本验收 | agentskills、Promptfoo | 同题新旧版本对照、失败样本与检查项 | 固定测试材料，检查内容完整性、冲突、人工修改量 |
| 视频验收 | DirectorSKILL、VBench | 生成前、片段、整序列检查 | 同一视频人工标注问题，再比较自动检查漏检误检 |
| 声音与剪辑 | OpenTimelineIO、Remotion线索 | 镜头时长、轨道、字幕与音频关系 | 用真实素材验证时间码、引用与导入结果 |
| 进度与恢复 | LangGraph、waoowaoo | 节点状态、检查点、重复提交处理 | 中断后恢复，不重复生成，不误报完成 |
| 日志与复盘 | Langfuse、Microsoft课程 | 每次运行关联输入版本、费用、错误和结果 | 从交付物能反查其输入、方法与工具调用 |
| 经验与知识 | agentskills最佳实践、LightRAG | 带适用条件与证据的经验卡、检索索引 | 检索必须命中正确项目/版本，不能混入旧设定 |
| 制作协作 | Kitsu | 项目、资产、镜头、任务和审阅关系 | 团队需要时再深入后端与数据模型，不先搭完整平台 |

## 建议的吸收顺序

1. 先确认现有DirectorSKILL与已安装能力，提取需要的参考章节，不重复安装同名Skill。
2. 用agentskills规范和Spec Kit的验收思路统一一个节点合同；保留项目已有交付格式。
3. 以“单场剧本→文字分镜→资产需求→一致性检查”为试点，整理真实正反案例。
4. 按Promptfoo和Skill评测方法，比较当前方法与修改版，记录质量、耗时和人工改动。
5. 试点方法有效后，再选择运行框架并接入一类图片或视频工具；验证异步任务、预算与恢复。
6. 成片样本足够后，细化视频质检；知识库规模扩大后再考虑RAG。

这是后续实施建议，本轮仅完成搜集、审阅和资料归档。

## 目前仍缺的内容

- 目标平台与模型的最新能力合同，需要从实际工具接口或平台官方资料核对。
- 符合你审美的真实优秀/失败样本，外部仓库不能替代。
- 本项目可接受的费用、耗时、人工介入和重试边界。
- 交付平台的实际音视频规格，不能用通用GitHub文章替代平台要求。
- 经过实测的全流程稳定性数据；本次未安装和运行任何候选系统。
