# 怎样把制作流程变成可执行节点

版本V0.1｜2026-10-30｜状态：有来源的研究提炼，制作效果待具体任务验证。

一条流程写清先后顺序还不够。下游需要知道拿哪份材料、材料是否有效、完成后交出什么，以及遇到哪类问题应返回哪一步。把这些说明清楚，才有可能让Agent稳定接手。这里借鉴软件规范与影视流程的组织方法，不把软件研发步骤直接套进创作。

<a id="G01"></a>
## G01 · 按交付结果划分节点

SOP的节点以能够检查的成果结束，而不是以“调用了某个模型”结束。 调用成功可能只返回了一段不完整文字；下游若直接接收，会放大错误。

**本项目用法：**先写产物，再写必需输入、检查与后续读取者；根据输入输出决定节点边界。

**教学示例：分镜节点交付镜头表和素材需求，检查原文动作与对白覆盖后才进入资产准备。**

**适用边界：**仅提供分析意见的任务不必强行生成完整制作包。

**检查办法：**核对每个节点都有可打开的产物及明确完成依据。

来源：[S07](来源与阅读边界.md#S07)、[S08](来源与阅读边界.md#S08)、[S23](来源与阅读边界.md#S23)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G02"></a>
## G02 · 输入需要版本和权威来源

输入不仅是一条文件路径，还包括有效版本、确认状态和适用项目。 同名文件或后续替换会让已生成结果失去可追溯性。

**本项目用法：**记录项目、源文件、版本或摘要、确认依据；提交工具时冻结实际输入。

**教学示例：SHOT_03使用剧本r2和角色图r4，不能在排队期间自动改用刚上传的r5。**

**适用边界：**小任务可用版本名；自动化涉及替换时宜记录内容摘要。

**检查办法：**修改源文件后，能识别原结果依赖旧版，而不是宣称它自动同步。

来源：[S09](来源与阅读边界.md#S09)、[S11](来源与阅读边界.md#S11)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G03"></a>
## G03 · 用条件而不是固定仪式控制流程

前置条件满足即可进入节点；只有真实缺口才等待补充。 每一步都要回复确认会增加操作成本，也无法处理用户从中间阶段进入的任务。

**本项目用法：**区分必要输入、可合理默认的细节与必须由用户决定的内容；把条件写成可判断句子。

**教学示例：用户已有确认分镜时直接进入资产检查；只要文字分析时停在分析交付。**

**适用边界：**用户明确要求逐步审核时保留该节奏，不能借自动化跳过。

**检查办法：**用已有材料、缺失关键材料、只要求分析三类请求检查路由。

来源：[S07](来源与阅读边界.md#S07)、[S02](来源与阅读边界.md#S02)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G04"></a>
## G04 · 返工指向最早有证据的错误

发现视频问题后，先区分剧本、分镜、参考图、提示词、工具与后期问题。 在错误输入上反复生成通常无法修复上游矛盾。

**本项目用法：**记录症状和出现时间；检查直接输入；定位可证实原因，再修改对应层并复查依赖。

**教学示例：角色在首帧就持错道具，先改参考图；参考图正确而动作未完成，再检查动作设计和工具响应。**

**适用边界：**最早异常时间只是线索，不能证明根因；晚出现的漂移也可能来自参考冲突。

**检查办法：**修复记录能说明为什么改这一层，以及哪些下游需要重做。

来源：[S16](来源与阅读边界.md#S16)、[S23](来源与阅读边界.md#S23)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G05"></a>
## G05 · 上游变更要检查下游影响

已确认设定变更后，只重查受影响成果，并保留旧结果对应关系。 全部重做浪费成本，完全不重查又会混用状态。

**本项目用法：**用依赖表记录剧本→镜头→参考资产→生成任务→剪辑片段；变更时标记相关项待复查。

**教学示例：对白改写影响口型、配音和字幕；仅封面标题调整通常不影响镜头素材。**

**适用边界：**这是由输入冻结和交接原则综合出的项目设计建议，尚未实现自动依赖追踪。

**检查办法：**给定一项变更，能列出影响项和不影响项并说明依据。

来源：[S09](来源与阅读边界.md#S09)、[S11](来源与阅读边界.md#S11)、[S07](来源与阅读边界.md#S07)。用法与示例为本项目综合改编，不是已验证结果。
