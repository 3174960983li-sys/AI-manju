# 怎样让Agent中断后继续可靠工作

版本V0.1｜2026-10-30｜状态：有来源的研究提炼，制作效果待具体任务验证。

长时间运行的制作任务，必须把进度保存在程序可读取的状态中。聊天里说“正在生成”不等于平台接受了任务，收到成功响应也不等于文件已经下载并验收。这里提取运行设计原则，不要求立即采用某一个框架。

<a id="G21"></a>
## G21 · 运行状态要有明确证据

等待、运行、成功、失败、取消和受理不明需要分别表示。 将所有异常都叫失败，会诱发重复提交或错误退款；只看进度条也会误报完成。

**本项目用法：**保存本地任务ID、外部任务ID、最近查询、产物位置与状态来源；成功后核对文件和检查结果。

**教学示例：平台已生成但下载失败，应恢复下载，不能重新收费生成。**

**适用边界：**具体状态名称可按工具调整；没有外部ID时不能假装已有可查询任务。

**检查办法：**模拟提交、查询、下载各阶段中断，恢复动作与真实状态一致。

来源：[S11](来源与阅读边界.md#S11)、[S19](来源与阅读边界.md#S19)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G22"></a>
## G22 · 受理结果未知时不能盲目重提

网络超时不等于服务端没有接受请求。 直接再提交可能造成两次付费、两份结果和无法对账。

**本项目用法：**先查询请求标识或幂等键；只有明确未受理或服务端保证同键幂等时才重新提交。

**教学示例：创建视频请求断线，系统保留outcome_unknown，先查原任务而不是自动创建第二条。**

**适用边界：**没有查询和幂等能力时需要人工或服务商确认，不能用等待时长推定未受理。

**检查办法：**中断演练不出现同一逻辑任务的无依据重复提交。

来源：[S11](来源与阅读边界.md#S11)、[S12](来源与阅读边界.md#S12)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G23"></a>
## G23 · 检查点与任务事实分别保存

检查点保存流程执行位置，外部任务记录保存实际提交与结果。 只恢复模型对话，可能忘记外部动作已发生；只记录平台ID，又不知道后续检查做到哪里。

**本项目用法：**为项目与任务建立隔离ID；恢复时先读检查点，再核外部任务事实和已保存产物。

**教学示例：恢复到“生成后检查”节点时发现片段已存在，就复核该片段而非从头生成。**

**适用边界：**框架的pending writes解决其内部状态恢复，不自动解决所有外部副作用。

**检查办法：**恢复后已完成节点不无故重做，项目间状态不混用。

来源：[S19](来源与阅读边界.md#S19)、[S11](来源与阅读边界.md#S11)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G24"></a>
## G24 · 原始错误与用户解释分开

保留工具原始错误信息，再给用户可理解的说明。 过早统称“参数错误”会丢掉原因并引导用户错误修改创作输入。

**本项目用法：**记录脱敏错误码、消息、请求ID、阶段和上下文；用户说明只解释影响与下一步。

**教学示例：下载服务超时，应提示文件获取受阻，不能让用户重写分镜。**

**适用边界：**不要记录密钥或无限长响应；重试策略还要检查操作副作用，不仅看错误码。

**检查办法：**能从失败记录追到原始原因，且对外说明不泄露敏感内容。

来源：[S12](来源与阅读边界.md#S12)、[S05](来源与阅读边界.md#S05)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G25"></a>
## G25 · 生成和查询由清晰的工具合同连接

工具需要明确输入、返回值、错误与完成条件，而不是只提供一段操作说明。 模型可以写出很好的提示词，却不知道它是否提交成功以及如何取回文件。

**本项目用法：**分别定义提交、查询、取回、取消等能力；字段和平台限制来自实际接口；保存冻结输入。

**教学示例：提交返回task_id，查询返回状态，取回返回文件及来源；不把一句“已提交”当全部记录。**

**适用边界：**MCP只是接口方式之一；ComfyUI基础示例仅演示提交，不能视为完整生产队列。

**检查办法：**用无费用模拟检查错误字段、未知任务和重复请求，再安排真实接口验证。

来源：[S05](来源与阅读边界.md#S05)、[S20](来源与阅读边界.md#S20)、[S09](来源与阅读边界.md#S09)。用法与示例为本项目综合改编，不是已验证结果。
