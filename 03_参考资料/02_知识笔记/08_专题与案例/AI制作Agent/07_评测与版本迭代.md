# 怎样判断新方法真的更好

版本V0.1｜2026-10-30｜状态：有来源的研究提炼，制作效果待具体任务验证。

“更专业”“更完整”不能单独证明升级有效。需要让新旧方法面对相同任务，用能观察的条件比较结果，并记录代价。评测既要发现漏做，也要发现多做了用户不需要的事情。

<a id="G31"></a>
## G31 · 新旧版本使用相同输入与环境

控制任务、素材、模型配置和输出要求，再比较方法差异。 如果同时改模型、资料和Skill，就难以判断进步来自哪里。

**本项目用法：**保留旧版快照；每组使用干净上下文和同一材料；标记不可控差异。

**教学示例：旧版与新版分镜Skill都处理同一场戏，不能只给新版补充角色表。**

**适用边界：**生成具有随机性；单次胜出不证明稳定优势，有争议的任务应重复采样。

**检查办法：**结果记录含输入摘要、Skill版本、模型和执行配置。

来源：[S03](来源与阅读边界.md#S03)、[S18](来源与阅读边界.md#S18)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G32"></a>
## G32 · 评测覆盖边界和误触发

正常任务、信息缺失、范围受限和冲突输入需要一起测。 只测最顺利的例子会掩盖自动扩展任务和错误默认。

**本项目用法：**选择代表性案例，写预期行为；边界例子包括只审查、素材号缺失和版本冲突。

**教学示例：用户只要求指出问题，输出完整改写属于越界，不能因文字精美而算成功。**

**适用边界：**案例数按风险增加，源文的起步数量只是建议。

**检查办法：**同时统计漏做与多做，而非只统计输出长度。

来源：[S03](来源与阅读边界.md#S03)、[S17](来源与阅读边界.md#S17)、[S18](来源与阅读边界.md#S18)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G33"></a>
## G33 · 机械检查与专业判断分工

字段完整、文件存在等适合自动检查；因果、表演和美感需要专业审阅。 让同一个模型给自己笼统打分，容易忽略缺陷。

**本项目用法：**机器检查确定项；审查者引用原文或画面证据；审美比较可隐藏版本身份。

**教学示例：机器检查镜号唯一，人工判断观众能否理解钥匙交接为何改变人物关系。**

**适用边界：**盲评也有偏差；审查者不同意见应保留而非强行平均。

**检查办法：**每个通过项有证据，无法观察的项标未验证。

来源：[S03](来源与阅读边界.md#S03)、[S04](来源与阅读边界.md#S04)、[S15](来源与阅读边界.md#S15)、[S30](来源与阅读边界.md#S30)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G34"></a>
## G34 · 合格率要结合成本与人工返工

方法价值同时体现在质量、费用、耗时与人工修改量。 新方法可能只通过增加大量生成次数获得一点提升。

**本项目用法：**先定义合格交付，再记录每任务总尝试、费用、耗时和人工介入原因，比较同类任务。

**教学示例：首次通过率上升但每条成本翻倍，应明确权衡，不能只公布通过率。**

**适用边界：**不凭少量样本给稳定百分比承诺；记录样本量和异常任务。

**检查办法：**能够从总指标回查每次实际运行与失败样本。

来源：[S03](来源与阅读边界.md#S03)、[S29](来源与阅读边界.md#S29)。用法与示例为本项目综合改编，不是已验证结果。

<a id="G35"></a>
## G35 · 更新需要回归与回退依据

新规则修复当前问题后，还要检查是否破坏已能完成的任务。 针对一个失败例过度加规则，可能让其他题材全部套用同一镜头结构。

**本项目用法：**保留代表性旧案例与未参与调参的验证例；新版本比较后再替换入口，保留回退位置。

**教学示例：新增多人动作检查后，用安静独白场景复查，确认没有强迫额外人物与动作。**

**适用边界：**这是从对照评测综合出的发布建议；本轮没有发布新Skill版本。

**检查办法：**更新记录能说明改善、退化、样本限制与回退条件。
