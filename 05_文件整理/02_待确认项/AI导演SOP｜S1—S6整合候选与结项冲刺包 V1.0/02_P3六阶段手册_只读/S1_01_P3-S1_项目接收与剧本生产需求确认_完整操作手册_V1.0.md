# P3-S1｜项目接收与剧本生产需求确认：专业详细操作手册

> **版本**：V1.0｜编制日期：2026-10-21  
> **性质**：P3专业操作教程（已作来源/结构静态复核；未在独立真实项目进行全流程试运行）  
> **管理基线**：`P2-V1.1-RC1`（技术归档候选，实际负责人签核仍待确认）  
> **范围**：S1-01—S1-07；交付A01—A05，采用T01，G1决策仅写T09。  
> **下游**：S2-01至S2-06；S5/S6仅接受S1风险提示，不因S1完成而自动获得正式制作授权。  
> **不包含**：原创剧本编写、详细制片预算与排期、合同/版权法律意见、S2导演风格锁定、S3单场表演、S4镜头分镜、S5实际美术生成、S6执行提示词。

## 0. 手册目的、适用层级与完成判定

S1的核心任务不是写出吸引人的故事简介，而是使项目团队能可靠回答：**当前哪份剧本有效、委托方要求什么、故事靠什么驱动、哪些关键内容不得丢失、制作的主要风险在哪里、下一阶段应研究什么。**

本手册将原始《01｜专业影视项目解读：流程与结构规范》的七步专业方法，嵌入已形成的S1-01—S1-07步骤编号。原文中“读剧本—目标受众—重要场次—资产风险”的专业判断未变；管理台账和G1签核是P2阶段补充的交接标准，不应误认为原始规范逐字规定。

**每次真实项目应用**只维护一套T01（A01—A05）。操作卡、案例和检查表用于学习与自检，不是额外须完成的项目审批文件。短片可以把T01、场次简表和问题清单合为一份文件；复杂长剧可拆分保存，但每个权威字段只允许有一个有效版本。

### S1总体流水

```text
收到材料 → S1-01 A01资料目录
                  ↓
             S1-02 A02唯一生效剧本/冲突
                  ├── S1-03 A03目标、交付与约束
                  └── S1-04 A03故事/人物机制 → S1-05 A04故事脊柱与场次
                                                        ↓
                                            S1-06 A05资产与风险初盘
                                                        ↓
                               S1-07 汇总A03、核对A01—A05 → T09 G1拟判定/正式签核
                                                        ↓
                                   S2导演风格与视觉证据设计（限定放行范围）
```

S1-03与S1-04在A02基线确立后可并行，S1-06至少依赖目标/时长约束与重点场次。剧本尚未确定时可做候选材料梳理和独立研究，但不得将候选版当成正式下游事实。

| 步骤 | 决策主问题 | 写入位置 | 主要接收方 |
|---|---|---|---|
| S1-01 资料收集 | 收到哪些资料，什么用途，缺什么？ | T01/A01 | S1-02、S1-03 |
| S1-02 生效版本 | 哪份事实为准，冲突在哪里？ | T01/A02 | S1其余步骤、S3 |
| S1-03 目标约束 | 要交付什么，不能改变什么？ | T01/A03第01、05节 | S1-07、S2、S4 |
| S1-04 剧情人物 | 故事动力/信息差/核心卖点是什么？ | T01/A03第02—04节 | S1-05、S2、S3 |
| S1-05 故事脊柱 | 哪些场次推动转折并必须保留？ | T01/A04 | S1-06、S2、S3 |
| S1-06 风险初盘 | 哪些资产、状态和动作最可能导致返工？ | T01/A05及A03第06节 | S2、S5、S6 |
| S1-07 最终交接 | 哪些事实已闭合，允许S2研究到哪一步？ | T01/A03第07节；T09/G1 | S2 |

### 概念和证据约定

- **F**：可追溯的剧本原文、委托硬约束或真实可核验资源；写出文件ID、版本及场/段落出处。
- **I**：有依据的解读，例如“这个段落更侧重角色关系而非动作展示”，必须附可回看证据，不当成不可更改事实。
- **H**：尚需批准的创作建议，如改动信息揭示顺序、增加桥段或选具体镜头，S1通常只提交给下游，不直接生效。
- **U**：缺项、相互矛盾或需要他人决定的事项，明确责任人、影响范围、阻断程度及核实条件。
- **R/C/O**：模板字段义务（必填/条件必填/可选），不是F/I/H/U的事实状态；**一个必填字段写U并不意味着条件满足**。
- **工作门**：通过/有限范围通过/待核实/退回，仅T09具有正式结论效力；无真实审批人和日期只能作拟判定。

## 1. S1-01｜收齐原始资料

**任务边界**：确认材料是否存在、是谁提供、具有什么用途；不判定剧情优劣，不默认为最新文件一定有效。

**启动条件**：收到项目任务或新资料；无先行G门。**必要输入**：交付过的剧本候选、项目简报、角色/场景已有资料、参考样片、修改反馈、交付限制；缺失允许如实记U。**主责建议**：项目统筹。

### 专业判断

资料具有不同的**证据效力**：原剧本提供剧情事实，委托协议或已确认简报提供交付硬约束，参考图可能仅提供“画质”而非服装造型授权，聊天修改意见须核对确认状态。判断顺序为“资料真实存在吗→来源和版本可回溯吗→用途有明确授权吗→与其他文件是否矛盾”。同一素材可被用于不同目的，但必须逐一说明。

### 可执行操作程序

1. **建立收件清单**：把目前收到的每份文件记录为稳定`DOC-ID`，不以易改的显示名称作为唯一索引；保留原文件名、扩展名和可访问路径。
2. **读文件头与交付信息**：核对标题、文件内部版本号、提交时间/来源、集数场次范围；“文件系统修改时间”只证明文件状态，不自动证明内容生效。
3. **分类用途**：标记剧本/项目简报/人物设定/美术参考/样片/反馈/进度预算/版权限制等；补充“事实/仅参考/禁用/待确认”。
4. **分辨参考维度**：对每个参考问清“参考摄影光影、色彩、人物审美、服饰细节、场景结构还是叙事手法”；未确认不允许扩大复制范围。
5. **做缺项扫描**：列出目前无法回答但可能影响下一步的缺口，例如缺正式剧本、缺目标画幅、缺修改确认；为每项分配可确认的人和触发条件。
6. **检查索引可用性**：随机选一条硬约束，在A01中能定位来源；随机选一张参考图，能定位授权用途，而非凭记忆。

**落位**：只写`T01/A01`；记录资料`DOC-ID`、名称、来源、版本/日期、类型、用途、有效状态、缺项或冲突。**分支**：仅收到一份剧本仍登记DOC-ID；收到几十份参考可先按类别建立索引，不必每张写长段评价。**交接**：把版本候选送S1-02，把已确认交付限制线索送S1-03。

**L0阻断**：不存在资料却填“已收到”；关键限制找不到出处；将仅限光影参考的图片标为造型复现依据。**L1专业质量**：不看口头聊天亦能找回有效资料和缺项，参考边界不含混。**L2**：S1无须实际视频验证；若资料是远程路径，可通过实际打开/访问证据核查，但文件存在不代表授权完整。

**典型错误→修正**：`“客户发了三版，先用最后一个文件。”` → 检查每版提交者、修改意见与生效确认，仅登记候选；效力在S1-02处理。**回退**：新文件加入A01，触发S1-02受影响版本复核；不必自动重做所有已确认场次。

## 2. S1-02｜确认有效版本和信息优先级

**任务边界**：为剧情事实建立唯一权威来源，并逐项解决冲突；不代编剧修改剧情，不私自认定“改得更好”的稿为生效。

**启动条件**：A01包含待核对版本。**必要输入**：剧本候选、项目负责人或委托方明确的生效确认、修订说明。**主责建议**：项目负责人实际确认，资料统筹整理。

### 版本判断模型

先判断**范围**（全剧、某集、某场）→再判断**生效证据**（明确签核/已确认通知）→再判断**与基础版本如何组合**。修订补丁只影响明确覆盖的片段；不能凭更晚修改时间推断已经替代完整剧本。若不同文件对同一场的台词、动作或人物状态冲突，需记录两个出处和待判决人。

### 可执行操作程序

1. **列版本谱系**：每份剧本标文件ID、内部版本号、集数/场次覆盖、提交人和修订说明；未知字段写U。
2. **做差异比对**：优先比对白、事件顺序、人物身份/状态、场次增删、结尾信息；对影响叙事或资产的差异逐条记录`CF-ID`。纯标点变化也应确认是否涉及正式台词。
3. **确定生效优先级**：读取已确认项目要求指定的版本；对于“全集V3 + 第12集补丁V4”的情况，只在已明确批准的补丁范围合并。
4. **请实际授权者裁定冲突**：提出精确二选一问题——“第X集第Y场采用A还是B？会改变对白/动作/关系。”不替授权人作决定。
5. **锁定唯一索引**：在A02记录当前有效剧本ID与版本，若只部分确认则在场次维度记录可用范围；冲突项仍为U。
6. **分层标记事实**：把剧本原句与明确要求列F；剧本外推断列I；未批准改动列H；无法确认列U，并给下游引用规则。
7. **做回指测试**：随机抽一个关键场的对白/状态，请另一执行者准确找到原文；若两个版本都被当成生效源，立即停止正式衍生任务。

**落位**：`T01/A02`的唯一生效剧本、确认依据、禁用版本及CF冲突行；A01维持历史材料索引，不能因为某版失效而删除其记录。**分支**：若完全没有正式审批，但项目允许只做研究，使用明确的“候选剧本”进行非正式分析，不批准S2全剧基线；可在T09写限定研究范围的拟判定。

**L0阻断**：两个互斥版本同时声称唯一生效；原台词不能回查；冲突被悄悄删掉。**L1专业质量**：版本差异与上下游影响可精确定位到集/场，不将一处修订扩大为所有章节失效。**L2**：核查的是文本和确认记录，不是模型表现。

**典型错误→修正**：`“最新版第3集改了人物身份，因此全部剧本按新版默认。”` → 先查新版是否仅替代第三集；若授权未明确，第三集阻断，独立且无共享依赖的其他集允许受控研究。**回退**：剧本改变从A02建立CHG，再按实际影响复核A03/A04/A05、S2/S3及后续场/镜，旧G门对新快照不能自动生效。

## 3. S1-03｜识别项目目标、受众和最终要求

**任务边界**：确认业务与交付成功条件；不把预期受众画像当已证实市场结论，不提出尚无依据的“平台流量公式”。

**启动条件**：A01/A02可引用的简报与剧本基线；可在版本待确认时梳理非剧情依赖的交付要求。**输入**：用途、交付物、播放端、技术规格、语言/字幕、工期预算、内容边界与委托反馈。

### 需求解析的六个维度

1. **用途与交付对象**：正式平台上线、客户样片、试播验证或作品集，各自对完整度/授权/母版要求不同。
2. **受众与观看动机**：目标地区、类型与观看渠道只是入口；还要从剧情证明观众为什么继续看（悬念、关系变化、反转、动作展示等）。
3. **影像规范**：最终成片画幅、单集时长范围、帧率/分辨率（如明确）、字幕交付策略；**参考图画幅与最终视频画幅必须分别记**。
4. **声音与文字**：对白语种、SYNC/OS/VO政策、是否需独立配音、叠加字幕有无；“无字幕”不意味着删除布景内原有文字。
5. **资源与风险**：预算、时间、角色和场景规模、工具/入口限制；若模型能力未做测试只记约束与假设。
6. **内容/授权边界**：明确委托要求、平台公开政策需要核查的方面、第三方音乐/形象素材授权；缺乏正式核验时只列待咨询，S1不出法律结论。

### 可执行操作程序

1. **摘出原句**：从委托文件中逐条摘录可直接改变成片的条款，登记`RQ-ID`、原文、出处和明确确认状态；不要先自行改写成愿望句。
2. **拆分混合要求**：例如“竖屏、快节奏、电影质感、不要字幕”应拆为画幅（可验证）、节奏偏好（需导演转译）、画面质量意图（需S2定义）、字幕规则（可验证）。
3. **区分硬/软/未知**：硬性不可改的画幅/语种与可优化的审美建议要分开；没有确认时间或分辨率，写U而非沿用过往项目默认值。
4. **验证一致性**：排查冲突，例如客户要完整对白而时长极短、剧本改动影响交付集数；将矛盾转为可确认问题。
5. **形成成功定义**：优先用成片可观察的标准写：“关键剧情信息不遗漏，台词内容与生效剧本一致，成片画幅和交付时长符合要求”；传播播放量之类不能由创作本身保证。
6. **明确交接类别**：导演表达类送S2，镜头级技术边界送S4，声音与模型入口限制在下游执行时再次核验，不直接于S1规定摄影参数。

**落位**：`T01/A03`第01、05节；源条款保存在A01引用，A03用`RQ-ID`引用不复制出另一份独立权威合同。**L0阻断**：将未确认画幅/语种写成F；将参考画幅替换成正式成片画幅；必需交付条件有相互冲突却标通过。**L1专业质量**：要求具体可验、受众判断有故事证据，并能交给S2形成导演问题。**L2**：此处无真实模型质量结论。

**典型错误→修正**：`“目标是高质量电影感。”` → 分解“人物动作与情绪可读、质地真实、光源一致、画面符合平台规格”，明确哪些是客户原要求F，哪些属于制作团队的质量转译I/H。**回退**：交付规格冲突返回S1-03并由责任方裁定；正式变更建立CHG并精准复核受影响镜头与工作门。

## 4. S1-04｜完整阅读并提炼故事与人物

**任务边界**：确认整部作品的故事动力和看点；不开展逐镜拆解，不把角色的一次醉酒直接解读为终身酗酒等未写明设定。

**启动条件**：有效剧本A02可回查。**输入**：完整剧本、已确认人物设定、A03当前业务目标。

### 两遍阅读与因果分析

**第一遍：连续读故事，不切镜。** 分集只写“这一集谁采取什么行动、发生什么变化、结尾留下什么问题”；遇到不明白的情节标注，不先编造解释。  
**第二遍：按行动线读。** 追踪主角的开场目标、阻碍、主要选择、失败代价、关系转折、信息暴露与结局。将人物的**身份/性格标签**与本剧里**具体做出的选择**分开。

### 可执行操作程序

1. **抽一句话故事**：`人物是谁→要争取的具体结果→阻碍来自哪里→失败代价/悬念是什么`；未知的失败代价写“剧本未明确”，不要为戏剧性自行加生死危险。
2. **提炼主角行动线**：列出起点、触发事件、关键选择、第一次失败或反制、最终改变；每条旁边记录集/场来源。
3. **识别核心冲突**：写成相互作用的目标，不把“愤怒”“奇幻”“古装”当成冲突；辨别主冲突、辅助冲突和阶段性变化。
4. **整理主要关系**：写角色姓名、与主角的关系、各自已知信息、关系何时变化；未知动机不擅自填定论。
5. **建立信息链**：至少记录三种信息：“观众知道、人物知道、待揭示”；抽取身份揭示、误会成立和回收伏笔的来源场次。
6. **对看点排序**：找出1—3项真正推动观看的机制，每项配一个具体剧本事件证明，标I；不要因类型标签直接套用通用爽点。
7. **三句话自测**：让未参与阅读的人只看结论，能说出“故事在争取什么、为什么难、为什么还想看”。若只会复述场景顺序，重新提炼。

**落位**：`T01/A03`第02—04节，必要时参考A04但不提前填写镜号。**分支**：30秒作品可简化成“目标—阻碍—结果—余问”；多集长剧可把主线分为全剧/篇章/单集三个粒度，以主线为准不机械每集另编复杂人物档案。

**L0阻断**：将未知人物动机认作剧本事实；漏掉关键身份改变；引用非生效版台词。**L1专业质量**：看点与主角行动线能够找到剧本证据，信息揭示逻辑清楚。**L2**：文本理解可做交接可读性测试，但不宣称真实观众必然有某种情绪。

**典型错误→修正**：`“男主很强势，女主很紧张，所以观众喜欢。”` → 改写成“哪些目标相抵触、谁先采取了什么策略、何种信息让观众形成期待”，并附对应场次。**回退**：剧情解读前后矛盾先回S1-04；若原始剧情本身相冲突，则回S1-02确认版本。

## 5. S1-05｜建立故事脊柱及重点场次

**任务边界**：建立剧情的结构性地图，让后续知道先分析什么；不在此拆成镜头，更不写单场演员微表情。

**启动条件**：S1-04故事行动线有足够依据。**输入**：有效剧本分集场次、主角行动线、信息揭示结构。

### 重点场次的专业判断

判断一场是否“重点”，问四件事：**删掉会损失什么不可恢复的信息？改变了哪个人物目标/关系？下一场是否依赖其结果？是否具备难以替代的观众回报？** 这比以“打斗规模大、服装华丽”评为重点更可靠。重点分为剧情不可省略、视觉/动作制作高风险、适合做导演风格代表验证三种用途；可重叠，但须说明原因。

### 可执行操作程序

1. **统一场次标识**：以剧本自然场次建立`E##-SC##`；当剧本没有稳定场号时，由统筹创建临时索引，注明该索引不是原剧本编号。
2. **绘出故事脊柱**：`起点→触发→主要升级→关键转折→高潮回报→余问/结尾`，每个环节指向至少一个剧本场次或标“暂无明确对应”。不是强制所有短片必须六段齐全。
3. **逐场写功能句**：使用“本场使___从___变为___”；尽可能写清信息、关系、局势或决定的变化，避免把“角色说话”当功能。
4. **标记信息保留条件**：记录“观众在此场之前不能知道X；在此场之后必须知道Y”，并区分角色知情顺序。
5. **初筛关键场次**：给每个重点场至少一条剧本依据及为何关键；不要用主观喜好直接判定。
6. **核对因果链**：沿场次顺序模拟一次“关键事实发生→下一场依赖”关系，检测因果断裂与提前剧透。
7. **给下游任务标签**：哪些场先给S2做风格验证，哪些场属于S3高复杂度分析，哪些场需S5/S6提前了解风险；这里只下达需求，不直接制作。

**落位**：`T01/A04`；A03仅保留总纲与看点结论，避免复制全量场次表。**分支**：超短片可一张功能链；60集可按篇章分层建立场次索引，保持同一场ID稳定可检索。

**L0阻断**：重点场事件与有效剧本相悖；缺少场次来源却当已确认；改变揭示顺序却未按H标注。**L1专业质量**：重点排序支撑观看动力与资源投入选择，非仅按场面规模。**L2**：可让导演与统筹在桌面演练中按A04找回关键场，没有真实观众研究就不宣称验证情绪效果。

**典型错误→修正**：`“婚房是最豪华的场景，所以一定最重要。”` → 应说明此场承担什么信息揭示/人物关系变化，以及是否为高复用高风险空间。**回退**：脊柱因果漏项回S1-05，涉及前置错误的回S1-04；若版本更换回S1-02。

## 6. S1-06｜初盘资产、状态和AI制作风险

**任务边界**：找到可能导致生产失败或影响成本的关键需求；不正式设计角色/场景/道具，不凭文字预判宣称模型一定可实现。

**启动条件**：已有S1-03目标与A04重点场次。**输入**：有效剧本、初步角色/场景/道具、台词/动作信息、预算工期及可用工具（如已确认）。**主责建议**：统筹、导演与执行协同。

### 资产与风险的两张视图

**资产视图**按`角色/服装伤妆→场景/出入口与空间拓扑→道具/交接状态→特殊声音`初盘，记录出现位置与复用，不填已有实物`AST-ID`，除非真的存在并核实。  
**风险视图**每项使用`剧情任务→关键动作/状态→潜在失败方式→对观众的影响→先验防护→最小验证建议`，优先处理“重要且一旦失败会连锁影响”的问题。

### 可执行操作程序

1. **遍历关键场次**：从A04挑重点及高复用场，列角色姓名、场景名、关键道具、声音事件；每项标出原文出处。
2. **标记状态变体**：同一人物有换装/受伤/醉态吗？同一道具是否被揭开/掉落/交接？同一门是开/关？分别写**何时变、变化前后为何**。
3. **标记空间可实现性**：场景是否要主反打/斜侧/俯拍/室内外连通？可疑的门窗、床、楼顶/通道尺度统一列为待S5复核需求。
4. **标记动作/表演/声音难点**：抓握接触、多人运动、失衡、口型指定台词、OS/VO、跨镜环境声、无叠字限制等；风险必须指向具体场景与动作，不只说“AI困难”。
5. **评估优先级**：不创造未经验证的模型成功率。以剧情损害程度、复用范围、技术不确定性、修正代价给出定性P0/P1/P2建议，并注明依据。
6. **设计最小验证任务**：优先设定“要验证哪个单一问题、用哪种素材、需要怎样的可观察结果、失败后改什么”；3—8秒片段或一组主反打是原规范提供的可选尺度，**不是任何入口官方保证的固定时长**。
7. **明确风险所有者与接收方**：导演意图风险给S2/S3，空间/造型类交S5接口，动作负荷与口型类交S4/S6；未取得资产不能在A05写“已经验证”。

**落位**：`T01/A05`，A03第06节仅保留总体规模和TOP风险。**分支**：普通单人短片初盘简单即可；多集连续换装和复杂多人接触则扩展到场次和状态维度。S5专项仍待资料，S1阶段只登记需求和风险。

**L0阻断**：将临时假资产号作为实物；多镜头关键状态不记录；将桌面推演说成真实模型测试。**L1专业质量**：每个高优先风险能定位具体场次、预期失败样态和最小验证；排序可用于资源投入决策。**L2**：尚未测试的所有视频生成结论保持“待实测”；有真实素材也必须单独登记其来源和版本。

**典型错误→修正**：`“床摇晃不好生成，提示词多写几遍。”` → 先问人物用哪只手抓哪两个受力点、床的结构是否允许整体摇晃、镜头能否容纳全床；分别送S3/S4/S5，再由S6验证。**回退**：风险遗漏回S1-06；若根源是场戏功能或内容界定错误则追溯S1-04/05。

## 7. S1-07｜形成项目解读并向S2交接

**任务边界**：将已核验事实和有依据的专业分析压缩成下一阶段可执行的输入。此时不锁定导演风格，不擅自批准 G1。

**启动条件**：A01—A05关键内容可核对；重要U已有影响和责任记录。**主责建议**：导演/项目负责人复核。

### 交接审核程序

1. **统一故事与业务口径**：检查A03的一句话定位、主看点、人物线、画幅、单集时长等是否与A02生效剧本和RQ一致。
2. **对齐场次与风险**：A03的重大转折应能跳转A04场次；A05的高风险项应能跳转A04对应场并指出应由谁处理。
3. **核对全部阻断U**：将未确定项目放到T01新增的G1有限范围与未知项检查表，逐项写影响范围、允许的独立研究、明确禁止的活动及核实条件。
4. **区分交接问题类型**：S2要解决的“导演/观众立场”与“时代/视觉世界证据”分开交；不可在S1以‘按某导演拍’替代S2的独立比较。
5. **形成精简主卡**：A03七节均有内容或有根据的U；详情仍留权威A01/A02/A04/A05，避免反复复制导致不一致。
6. **按范围拟定G1判定**：对全项目、部分集场分别评估：不存在影响该范围的阻断项，才可建议“通过”；若允许有限研究，必须写清允许/禁止与为何不影响；关键条件未决则“待核实/退回”。
7. **向T09提交实际审查材料**：由真实负责人审核并填写gate_id、范围、证据快照、decision、allowed_next_work、prohibited_work、未决项、审批人和日期。缺真实签核不得宣布正式G1通过。
8. **向S2做可读性接力**：假设S2人员未参与前期讨论，能否仅凭T01定位“用什么剧本、为何选择导演风格、世界年代要查什么、先验证哪些高风险场”。记录误解并修正来源。

**落位**：A03第07节 + T01 G1检查；**正式工作门权威位置**是`T09/G1`而不是本手册或A03中的一句“已通过”。**L0阻断**：U被当成已完成条件；T09审批人/日期为空仍标正式通过；S1已替S2锁死风格。**L1专业质量**：S2能在不重复读完全部项目资料前提下准确定位目标、冲突、风险和风格问题。**L2**：跨岗位实际交接可作为工作可用性证据，但不是视频生成性能证据。

**典型错误→修正**：`“项目解读完成，所有场次都能直接做分镜和视频。”` → 改为“已完成S1资料整理；对X场允许启动S2候选方案研究；G1正式范围以T09真实记录为准；S3—S6需各自满足对应工作门”。**回退**：若A03错填，修正原权威A对象并复核G1；有剧本变更先新建CHG、限定影响范围并等待适用门重新批准。

## 8. S1阶段总体验收：L0 / L1 / L2 与G1

### L0｜硬性结构与事实（任一阻断项未闭，不得就受影响范围提正式G1通过）

- [ ] A01每份关键资料有稳定ID、来源、版本和用途。
- [ ] A02只有唯一适用的有效剧本，或明确列出未决范围与CF冲突。
- [ ] A03硬性画幅/时长/语言/交付规范有明确来源或标U，没有把参考用途写错。
- [ ] A03的人物、事件、剧情主线可回查A02，没有把I/H写成F。
- [ ] A04重点场次有集/场编号与证据，信息揭示顺序不与生效剧本相悖。
- [ ] A05高风险对应具体场次、状态和接收环节，不冒充已完成资产。
- [ ] 所有影响本次放行范围的U均有阻断判定、责任、允许/禁止活动和复核条件。
- [ ] G1如果正式通过，T09记录必须有证据快照、适用范围、真实审批人及日期。

### L1｜专业质量（不以一个分数替代判断）

| 评价点 | 高质量的可观察证据 | 不充分的表现 |
|---|---|---|
| 故事动力 | 可精确说出主角目标、障碍及推进因果 | 只是情节流水账 |
| 观看价值 | 每个主要卖点能定位到具体事件与信息机制 | ‘男频一定爽/女频一定甜’ |
| 人物与信息 | 角色关系变化、观众与人物知情差异清楚 | 过度推断角色前史 |
| 关键场次 | 重点排序解释了为何不得丢失该场 | 只凭场面华丽排名 |
| 资产/风险 | 描述失败样态和最小验证，并有下游接收者 | ‘AI生成会很难’ |
| 下游交接 | S2能依据A03起草不同导演方案与视觉证据任务 | S1提前写死镜头风格 |

记录结果用“达成/部分达成/未达成/缺证据”，写明引用场/文件及改进对象。L1合格也不能替代G1真实授权。

### L2｜实际工作可用性（S1场景下的适用意义）

S1并不要求真实模型出片。L2可指**实际项目资料的可访问性、其他制作人员独立阅读/交接后的正确复述、真实审批链是否可运转**。没有实际团队试运行则标“未进行交接实测”；不能将模拟练习写成实证结论。

### G1范围化决策

| 情况 | T09允许的正式结论（须审批证据） | 典型后续 |
|---|---|---|
| 剧本、约束、关键风险均闭合 | 通过 | 在获批准范围启动S2 |
| 部分场未决，但有可隔离、不受影响部分 | 有限范围通过 | 指明允许的集场/研究活动及禁止任务 |
| 关键交付约束或生效版本仍不明 | 待核实 | 做不依赖它的资料研究，禁止以未决条件锁定风格 |
| 已发现明确矛盾或材料不符合要求 | 退回 | 指向S1-01/02/03/04/05/06的最早纠错环节 |

**务必区分**：P2-RC1是“制度文件”的技术冻结候选；T09中的G1是“某部真实短剧项目”对确定证据快照的授权。两者互不替代。

## 9. 阶段适用性与不覆盖事项

1. **首次项目**：完整执行S1-01—07；S1-03与S1-04可以在A02建立后并行，最终由S1-07统一核对。
2. **剧本修订**：通常从S1-01新增资料和S1-02版本差异开始，按真实影响范围更新A03/A04/A05；不机械重做所有无关场。
3. **只有片段的测试任务**：明确适用集场与缺失整体上下文；可以做片段级解读和有限范围导演研究，不能捏造全剧人物弧光。
4. **只有画面参考、没有剧本**：先做项目材料和需求核对，不声称已经理解完整剧情；必要信息未闭不能正式进入S2全剧导演定位。
5. **预算/法律/平台规则**：记录用户或委托方已提供的要求与缺口；如需实际核验，应交专门角色/外部权威，S1教程不代替相关专项审查。
