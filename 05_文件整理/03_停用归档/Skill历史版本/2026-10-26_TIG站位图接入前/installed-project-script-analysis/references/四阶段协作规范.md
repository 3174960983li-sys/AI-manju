# 项目分析—导演—分镜—视频提示词协作规范

协作接口V1.0｜2026-10-26。本文件维护四阶段共同规则；专业设计细节仍由各Skill维护，不复制另一阶段的完整格式。该链路是文字创作与交接方法，不是自动运行四个Agent的程序。

## 1. 各阶段交付与接收

| 阶段 | 交出什么 | 下一阶段接收后做什么 | 不应越位 |
|---|---|---|---|
| 项目剧本分析 | 有效制作文本与原文对照、项目要求、真实阅读范围、因果/人物/世界判断、表达义务、已选与待选方向、准备需求 | 导演核采用状态，深化观众立场、场面与视听实现；有效分析不重填 | 分析候选不是已采用导演方案；不默认生成逐镜表 |
| 导演思维 | 整体意图、逐场行动/表演/空间/视听、关键观看条件、初末态、保持项和可变手段 | 分镜转成观看位置、光学、运动、镜间关系与七列执行信息 | 不替分镜默认固定镜数、焦段和秒数，不把导演稿冒称确认分镜 |
| 镜头语言设计 | 当前段有效七列分镜、场号到镜号关系、准确对白及声音范围、状态/切点、关键可读信息与素材需求 | 提示词核镜头充分性，映射生成任务和真实素材，编译六模块 | 不把故事板设为必经，不把提示词撰写等同生成 |
| 视频提示词制作 | 覆盖镜号与任务映射、独立提示词正文、必要设置/绑定状态、依赖与接续末态 | 后续制作按另获授权执行；真实结果返回对应设计层 | 不暗改采用剧情/台词/揭示/锁定镜头，不报未经检验的成片效果 |

技术入口：[项目分析](../SKILL.md)、[导演](E:/AI漫剧/02_制作方法/02_专业技能/自研Skill/photoreal-drama-director/SKILL.md)、[镜头语言](E:/AI漫剧/02_制作方法/02_专业技能/自研Skill/shot-language-design/SKILL.md)、[提示词](E:/AI漫剧/02_制作方法/02_专业技能/自研Skill/video-prompt-authoring/SKILL.md)。这些是本机维护原件位置；迁移后按目标环境现有包定位，不将绝对路径当必须存在的依赖，也不自动安装。

## 2. 用现有交付说明传递共同信息

简单项目可用一段话，复杂项目按已有场/镜组织；不要求另建数据库或每轮重填表单。

- **依据和范围：**作品、当前制作文本/分析/导演/分镜的有效版本或明确消息，所选方案、集场/整理段/镜号、本次覆盖及下一起点。Skill软件版本不是作品版本，文件日期不是采用证据。
- **采用状态：**区分原文事实、用户已采用修订、合理推断、普通执行细化与重要候选。已获授权的修补进入“制作采用文本”，不再同时要求下游执行冲突原句；原著对照保留，但不回滚已确认修补。发现新版来源与采用设计冲突时列差异，按当前有效用户要求处理，不能自动拼接。
- **设计约束：**项目已定规格、体验目标及必要观看条件、角色与观众知识、原句/声音归属、信息显露/暂缓、行动反馈与结果、已锁手段及自由度。只展开影响当前范围的内容。
- **状态与材料：**位置/朝向/视线、持物与关键道具、环境变化及持续后果、必要声场、首末态；现有文件、用途、是否真正检查过及尚缺什么。需求、文件存在、已核适用、平台已绑定、实际生成通过是不同状态，不强行做成线性成熟度评分。
- **依赖与验证：**阻碍哪个具体决定、可继续哪部分、待验证什么。未实测的时长、能力和观众反应不写成通过。

## 3. 选择阶段与确认边界

用户只要某一阶段就完成该阶段，不自动跑整链。已有充分输入可以从中间接入，缺上游文件不强迫重做；对必要补充注明依据和候选状态。

默认文字分镜逐段审阅，再按请求继续文字、故事板或提示词。用户明确要求多段，完整覆盖指定范围；明确“按这版直接出提示词”已含采用与分支请求，不再索要同一确认。明确要求整链试跑/草案时可交完整候选链，但不能把它写成真实项目已逐阶段确认。若仍明确要求逐段审批，则守该边界。

导演稿不足以直接编译时，补必要镜头设计并标状态；重要方向未知只暂停依赖部分，不无限追问。故事板是可选；写提示词不自动授权上传、补图、付费或生成。当前对接测试也不改变其他作品默认方法。

## 4. 一份当前内容，允许不同交付形式

项目分析最终导演本仍按要求交可编辑Word；讨论或试跑可以先文字。导演采用内容进入同一导演本对应章节，维护时核用户批注，不另造一套冲突事实。分镜与提示词是各自必要的阶段成果，可以独立保存，标所依据导演本/分镜版本，不必全部塞入Word。

场次、叙事段落、镜头和生成任务不相等。沿用现有编号，无规则才提出局部编号；已采用镜号不静默重排。合镜/拆镜注明旧新映射；生产任务重新分组不等于镜头结构已获改变许可。

一个有效原句来源可以在不同交付物中被引用，但最终音轨不能因跨镜、跨生成任务而重复说整句。全文唯一维护位置指每份执行稿内的原句位置，不是禁止导演本和提示词各自呈现该原句。对白跨镜/任务的具体分配见提示词接收规范。

## 5. 修改与反馈怎样闭环

先区分措辞重述、普通实现调整和实质设计改变。前两者不自动撤销上游采用；后者标受影响场/镜/任务及相邻状态。变更记录可直接写在当前交付说明，不要求新建日志系统。

| 发现的问题 | 首先回哪里 | 回传最小内容 |
|---|---|---|
| 制作采用文本矛盾、人物知识/因果前提缺失 | 分析/制作文本 | 原句或节点、冲突及影响、最小修补候选 |
| 故事条件齐，但所选场面无法传达必要体验或锁定导演条件互相冲突 | 导演 | 未承载条件、具体冲突、候选及取舍 |
| 场面可行，但取景/路径/清晰范围/声画/切点不可执行 | 分镜 | 受影响镜号与相邻状态，可变范围内先自行修正 |
| 设计齐全，但绑定、任务分配或编译丢项 | 提示词 | 任务—镜号映射、缺失原句/条件及局部修正 |
| 原素材没有实现、剪辑丢失、观看反馈与预期不同 | 据实际证据定位素材/剪辑或设计 | 实际版本、可观察现象和时间位置、未知项；不能未看媒体就归罪模型或剧本 |

上游实质变更后，下游相关部分标“需回查/待更新”，核清影响再决定是否仍可复用；无关段落保持。旧输出保留历史身份，不与新版都冒称当前可用。反馈里列出原因、改法、影响范围、采用状态；需要用户决定时只询问实质取舍。

## 6. 独立使用与链接

共享规范供多阶段任务按需读取，各包入口与本地参考应自含本阶段必要规则。其他包未安装/迁移失联，不应使单阶段任务停止，也不能假称已调用缺失Skill；可据已给材料完成当前阶段，必要时说明下阶段入口缺失。四包同目录时优先相对导航，本机维护原件可由明确绝对路径定位；不得自动重装或覆盖其他项目设置。

只有链接存在不算配合完成。至少用同一输入检查三次交接、镜号/任务/台词/状态覆盖、局部修改传播和边界情境。文字联查、独立审阅、用户采用、平台适配及成片观察分别记录。
