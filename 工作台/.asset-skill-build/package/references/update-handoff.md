# 更新与交接

## 更新来源
剧本初拆为需求基线。已确认导演或分镜带来新的服装、状态、空间交互或道具需求时，登记采用记录、适用场次、变更理由。未采用方案仍作为候选，不覆盖既定方案。分镜视角需要更多空间覆盖时补充视角需求，不新建同一场景身份。

## 保留式编辑
1. 先读现有Excel、用户批注/确认字段和原JSON（如有），核对来源版本与编号。输出新版本，不覆盖未知修改。
2. 以稳定编号比对，不按行位置匹配。确认值与用户批注优先保留；新证据与旧确认冲突时列出影响与最小修订，不静默覆盖。
3. 新身份/变体追加；已有身份改名不换号。已合并记录留旧编号与映射，活动引用改指有效编号。不跨项目复用身份编号。
4. 未在新范围出现的旧记录保持原样，不当成删除。范围缩小、版本替换导致停用时明确标注理由；原文没有恢复证据时不把湿/伤/破坏状态复原。
5. 来源变动后重查受影响场次与初末态；不顺便重写无关行。记录变更说明、日期、输入版本；保留用户确认记录定位。
6. 核对原始批注、确认值、稳定编号和原生表格功能。已有Excel必须先读取并保留式编辑；生成器不是Excel更新器。

`scripts/merge_data.py old.json delta.json new.json` 只处理中间JSON：按主键合并、保留未提交字段和用户批注；已确认行的实质字段变更、确认状态变更、已有批注改写均拒绝并报具体冲突。需要修订时先依据用户明确指示解决，再做定点更新。它不会读回Excel中的后来修改；只有Excel是最新时，不能用陈旧JSON重新生成覆盖。此限制必须在执行中说明。

## 对接现有体系
项目剧本分析的资产需求摘要引用本清单，不另建竞争清单。导演决定表达与表演，镜头设计决定视角和动作承接，资产Skill记录已采用的制作需求。角色站位图/TIG可提供确认的空间关系，不强制生成站位图。
交给美术：身份、服装/状态差异、空间组成、关键物件文字、数量/实例、来源和未决项。交给视频提示词：当前镜头用到的身份/状态/实例、入末态和连续性；真实素材是否存在、平台槽位及适用范围仍需后续核实。
不改变四阶段主链、不自动运行下游、不自动安装其他Skill，不把原文描述或清单编号当工具调用权限。
