# 七表规范与生成

唯一字段定义见 `../assets/schema.json`，所有数据表第4行为表头，第5行起为记录。空白模板不含假资产，空白预留行不计数。

## 表与行粒度
1. 使用说明与总览：项目/来源版本/范围/日期、各表有效记录数、缺口与导航。角色数是登记条数，不是物理人数；服装状态数包含基准，均明确标注。表格统计随记录增补更新。
2. 角色基础：一行一独立身份或群众群组，列出名称、别名、个人/群组、身份、外观依据、人数、首次出现及出现方式。
3. 角色服装与状态：一行一实际需要区分的外观组合，父键角色编号；包含基准编号、服装、妆发、年龄/形态、状态、差异、场次、制作建议。
4. 场景基础：一行一可辨空间；上级地点允许文本，空间特征、家具陈设、关键布局分别填写。
5. 场景状态：一行一实际空间状态组合；父键场景编号，分别填写光照、天气、物理变化、变化前后、适用场次、制作建议。
6. 道具需求：一行一道具设计或需区分的设计版本；包含基准道具编号、实际数量、用途、归属、外观文字、状态要求、场次、出现方式、制作建议。
7. 出现与变化明细：一行一资产在某场的一次出现或状态事件；可同场多条，明细编号USE保持稳定，事件序号用于排序。父资产只引用CHR/LOC/PRP，变体单独引用CHV/LCV；道具设计变体引用PRP。实例标识用于同款多件。记录叙事层、持有/位置、初态→末态、交互/连续性要求。

每条含原文定位、短摘录、证据性质、确认状态、待确认项、用户批注、变更说明、记录状态、合并至编号。摘录仅取支持判断的短句，不把整剧复制入Excel。未知业务值填“未明确”；没有父基准、未合并等结构字段允许空白，不能填不存在的编号。

## 编号与状态
项目内CHR/CHV/LOC/LCV/PRP/USE各自连续分配，至少4位数字，不按行号实时编号。删行、排序、改名后不复用旧号。新建先查现存和归档最高号。合并保留旧条目，记录状态“已合并”，合并至同类有效编号；停用保留“已停用”。不将待确认资产停用来掩盖问题。
证据性质：原文明示/合理推断/设计候选。确认状态：待确认/已确认/不适用；原文明示一般不适用，不伪称用户已确认。记录状态：有效/已合并/已停用。出现方式：入画/声音/提及/待确认。制作建议：沿用基准/补充参考/独立设计/变化过程设计/待判断/不要求可见设计。

## 格式
七表名称与顺序固定；筛选数据表，冻结4行及前2列，自动换行，数量已知时用数值，未知用文字。数据区不合并。表头深色白字、正文深色、缺口/待确认用文字与浅黄色提示，不能靠颜色判断。适当加高长文本行，不缩小字体硬塞。
基础表前几列优先放编号/名称/关键识别信息，长证据靠后。父键与明细引用提供内部跳转，父表靠筛选找关联明细。跳转只是导航，不改变单元格的真实编号值。
工作簿不包含费用、工期、素材文件路径或进度，不把“已确认”设计当“已制作”。

## 复用脚本
`node scripts/build_workbook.mjs <JSON输入> <新输出目录> [--render]`
输出 `剧本资产需求清单.xlsx`。为防覆盖，已有同名文件时拒绝写入。输入先经脚本校验；统计使用Excel表结构引用，新增表行后可自动扩展。预览只在--render时生成。
依赖@oai/artifact-tool与Python标准库；原生内部链接由scripts/add_links.py补充，因为当前生成引擎不支持HYPERLINK公式。可通过环境变量ASSET_PYTHON指定已配置的Python可执行文件。动态命名引用按稳定编号查找，排序后不依赖旧行号。可在临时/对话目录把node_modules指向已配置运行时模块，再从该目录运行脚本。生成脚本只创建新表，不编辑已有Excel，也不承诺保留Excel批注/样式。表格专业能力不可用时先说明实际缺口，不把CSV改名成xlsx。

## 验收
逐表视觉检查表头、关键字段、长文本尾部；核对导出后的冻结/筛选/内部超链接/验证项；独立复算统计。检查重复编号、父键、变体归属、来源、未知数量、同款实例与已合并引用。模板填入新行后检查筛选和统计扩展。脚本只能检查结构，身份归并、遗漏与设计判断仍需逐场语义复核。

随包提供 `assets/剧本资产清单_空白模板.xlsx` 与 `assets/剧本资产清单_边界案例.xlsx`。案例待用户审阅，不等同于正式作品资产清单。
