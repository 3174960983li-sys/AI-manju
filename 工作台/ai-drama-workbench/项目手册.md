# AI短剧Agent与SOP全流程｜项目手册

版本：v1.0｜日期：2026-10-31｜性质：体系建设工作基准

本手册记录已确认的整体框架和后续建设方法。12阶段框架已经用户确认；本手册提出的工作包和里程碑是下一步执行安排，具体阶段细则仍需逐项讨论、验证和确认。

## 1. 我们正在建设什么

本项目建设面向“个人＋Agent协作”的竖屏仿真人连续短剧生产体系，覆盖创作意向到成片交付与归档。目标是商业可用、质量优先，采用国内多平台组合，具体工具经验证确定。

体系应让操作者知道：当前依据是什么、下一步做什么、谁负责、交付什么、怎样判断合格，以及失败如何恢复。用户确认关键创作、立项、资源和最终采用决定；Agent自主处理已确认范围内的常规工作。

区分两套进度：

- 体系建设进度：框架、规范、SOP、模板、SKILL、工具适配和验证的建设情况。
- 短剧制作进度：某部作品在12阶段中的实际成果与状态。

完成文档不代表完成制作；纸面流程成立不代表工具或成片效果已经验证。

## 2. 已确认的12阶段制作主流程

| 阶段 | 主要任务 | 核心成果／出口 |
|---|---|---|
| 01 创作意向与初步构想 | 明确创作动机、作品目标、题材、核心故事、初步大纲、世界观及预期体验 | 可供项目分析的创意提案，假设明确 |
| 02 市场研究与项目可行性分析 | 分析市场、受众、竞品、形式、资源、路线、时间、费用、完成能力、效果及目标匹配度 | 有证据、范围和风险的项目分析；用户决定是否立项 |
| 03 故事与剧本开发 | 确定制作规格，正式开发大纲、人物小传、世界观、年代依据、初步风格参考、分集结构、分集剧本及逐场分析 | 可供导演与制作使用的创作基准 |
| 04 同类型作品分析与风格研究 | 结合正式剧本研究叙事、表演、调度、镜头、声音与画面方法 | 研究依据、推荐方向及适用条件 |
| 05 导演方案 | 设计观众体验、人物行动与表演、调度、视听和节奏 | 可指导专业制作的导演方案 |
| 06 制作拆解与样段验证 | 正式拆解资产与难点，验证代表性样段、主备路线和实际投入 | 经验证的生产依据与更新后的预算周期 |
| 07 核心资产设计与建库 | 建立人物身份、造型、空间及关键道具 | 可复用且版本明确的核心资产 |
| 08 分镜、对白读演与动态预演 | 联合设计并验证镜头、行动、对白时长、声音及组接 | 镜头执行依据、预演及补充资产需求 |
| 09 生产资产补齐与镜头关键图 | 补齐镜头所需资产、状态和关键时刻画面 | 已检查、实际可用的生成输入 |
| 10 视频制作与持续剪辑 | 批次生成、检查、定向返修、入剪及整场验证 | 可用源素材、采用区间和逐步成形的时间线 |
| 11 后期完成 | 精剪、配音、音效、音乐、特效、调色和字幕 | 声画协调的完成版 |
| 12 验收、交付与归档 | 内容与技术验收、输出、整理工程及复盘 | 正式交付包、可恢复工程及经验记录 |

### 阶段之间的重要区别

01初步大纲用于表达构想；03正式大纲指导剧本。02分析是否值得做、能否完成；04研究如何具体表达。02是带不确定性的估算，06通过实际样段校正。03年代与初步风格参考建立故事依据，04深入研究视听方法。

02结束必须由用户决定：进入正式开发／调整后复评／暂缓／终止。关键疑点可安排最小技术试验，但不提前铺开正式生产。市场回报和生成质量不作保证。

### 并行与反馈

- 03同步做制作可行性预检；显著扩张回02复评受影响部分。
- 06先用最小临时资产验证，避免正式建库后才发现路线失败。
- 07和08有限迭代：核心空间与身份支撑分镜，分镜回传补充资产需求。
- 声音前置，依赖对白时长与口型的镜头在生成前确定相应声音依据。
- 10首批素材立即入剪；11的声音和特效准备可前置，完成工作以对应时间线为准。
- 变更返回最早失效位置，保留未受影响成果，不默认全流程重做。

## 3. 体系建设的交付物

| 层级 | 交付内容 | 完成判断 |
|---|---|---|
| 总体架构 | 手册、阶段图、整剧—单集—场次—镜头层级、职责与确认关口 | 能说明整体如何运转，无职责和依赖冲突 |
| 公共规范 | 输入输出、来源、采用、版本、交接、质量、成本、变更与恢复规则 | 各阶段使用同一规则，无重复事实源 |
| 阶段SOP | 12阶段的输入、操作、产物、验收、异常与边界 | 接手者可按步骤完成任务并找到返工路径 |
| 模板与示例 | 必要的填写模板及明确标记的示例 | 字段支持实际决策，不以填表代替工作 |
| Agent与SKILL | 能力地图、调用边界、现有技能复用／改造、新增技能及验证 | 触发准确、输入输出明确，不越权或冲突 |
| 工具适配 | 实际入口、能力、附件、参数、限制、计费依据和替代路线 | 有日期与来源，关键能力经过实际验证 |
| 验证与发布 | 纸面演练、真实试生产、修订记录和发布索引 | 能说明哪些已验证、哪些仍有限制 |

不强制每阶段一个Agent或一个SKILL。先稳定职责和成果，再划分可复用能力。工具易变内容独立维护，不复制进每份SOP。

## 4. 接下来如何一步一步完善

### 里程碑A：锁定架构

当前已确认12阶段。接下来只讨论三个问题：

1. 层级：整部剧统一哪些内容，单集维护哪些内容，场次与镜头怎样关联。
2. 职责：用户、总控与专业能力分别负责什么，决定在哪里确认。
3. 关口：何时可以进入下一阶段，允许哪些并行工作，变更怎样回传。

输出一份整体协作架构。此时不批量编写阶段细则或创建独立SKILL。

### 里程碑B：统一公共规则

按需要确定最小规则：资料来源与采用依据、对象与版本引用、任务与交接、质量检查证据、预算与工时、失败恢复和目录结构。优先沿用已有编号，避免为管理而重建全部成果。

输出公共规范及最小台账结构；不预设复杂软件系统、数据库或自动调度平台。

### 里程碑C：逐阶段设计

按01至12顺序逐个完成。每阶段采用同一个讨论节奏：

“目的与边界 → 输入与成果 → 人的操作步骤 → 验收与返工 → 用户确认 → 保存阶段规范”。

一轮只解决当前层级的问题，不在阶段框架尚未确认时扩展大量字段、提示词或工具参数。先做01、02，稳定创意提案与立项机制，再进入正式创作流程。

### 里程碑D：配套模板和能力设计

阶段流程稳定后，补必要模板，并审计现有SKILL覆盖范围。决定复用、扩展或新增；需要新建时再按技能创建流程实施。Agent编排以实际任务依赖为依据，不按岗位数量机械创建代理。

工具研究可随阶段需要开展；不因尚未选定全部工具而阻断通用流程设计。GitHub社区技能只作为候选，检查来源、许可、依赖、权限和适用性，不直接当生产标准。

### 里程碑E：演练、试生产与修订

先用一个明确标为演练的案例检查输入输出和交接，找出流程缺口。再用代表性真实内容验证身份、空间、表演、声音、运动、组接、成本和恢复能力；试生产范围与预算由用户确定。

只对实际看、听、测量的范围给结论。将失败回写对应规范、模板或工具卡，复核受影响环节。必要时扩展到单集闭环，批量生产能力需另有连续制作证据。

### 里程碑F：发布v1.0并持续维护

整理入口、采用版本、验证范围、已知限制与待办。新项目使用后记录真实问题，以“问题—原因—修改—复核”方式更新。按影响发布修订，不把全部文档反复重写。

## 5. 配合方式与决策机制

用户负责作品目标、立项、关键创作方向、核心参考、资源上限、重要变更及最终采用；Agent负责梳理、检索、建议、文档实现、自检和已授权常规执行。

对高影响分歧提供具体选项、理由和代价。可通过文件或资料查明的问题先查，不反复询问。已确认决定持续有效；新信息影响原决定时说明影响再复核。

建议后续逐项确认的关口：项目立项、创作基准、导演方向、生产基准、单集开工、成片内容、最终交付。框架确认不等于授权付费生成、发布或外部发送。

体系建设每轮更新四件事：本轮确定了什么、实际改了什么、哪些仍未决、下一步做什么。讨论稿、采用规范、演练成果和真实制作成果明确区分。

## 6. 管理、验证与完成标准

来源各有维护位置：故事事实在采用剧本；视听决定在导演方案与分镜；身份空间在资产主档；实际参数费用在工具与任务记录；组接与采用区间在剪辑工程。总台账只关联版本、依赖、状态和位置。

工作进度、采用状态和验证结果分别记录。“已写完”不等于“已采用”，“已采用”不等于“已通过实际验证”。每次检查绑定对象版本、观察范围、方法、证据和限制。

周期和预算先以范围估算，记录假设和依据；包含研究、资产、生成重试、后期、检查及返工。样段后用实际工时、费用、采用率和缺陷更新估算。当前无项目与实测，不给虚构总价或完工日期。

体系v1.0完成需满足：

- 12阶段输入、产物、职责、验收和返工相互衔接。
- 用户确认节点与Agent权限清楚，跨阶段事实不冲突。
- 必要模板和能力入口可找到、可用且版本明确。
- 至少完成一次端到端流程演练，并记录实际验证范围。
- 核心媒体路线有真实样段证据；未验证部分明确限定。
- 能从中断恢复，能追溯采用依据，交付包能够检查和恢复。
- 用户根据证据确认发布；不把v1.0描述成对所有题材和工具均已验证。
