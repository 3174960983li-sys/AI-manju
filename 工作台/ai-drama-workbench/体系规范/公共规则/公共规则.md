# 公共规则

版本：v0.6｜状态：分项确认中

## 01 资料来源与采用依据（已确认）

1. 原始资料、研究参考、创作候选、已采用成果分别标明，不混淆用途。
2. 采用以用户明确决定及其适用范围为准；文件名“最终版”、更新时间或最大版本号不独立证明采用。
3. 每类内容有明确维护位置：剧情事实在采用剧本；身份与空间在资产主档；视听设计在导演方案和分镜；实际组接在剪辑工程。各位置管理相应范围，不相互覆盖。
4. 下游引用来源与版本，不另建竞争正文。镜头可记录所用人物和服装状态，不自行维护另一套人物设定。
5. 冲突不能静默覆盖。先检查是否存在明确变更决定；仍不明确则列出冲突、依据与影响，交对应责任方解决。

## 02 对象编号与版本引用（已确认）

1. 整剧、单集、场次、镜头及共享资产使用稳定对象编号；名称或排序改变时不随意换号。已有有效编号优先沿用。
2. 编号与顺序分开。插入、删除或重排时维护顺序记录，不全量重编号；废弃编号不复用。
3. 对象、版本、执行任务分别记录关联。同一镜头可有多个设计版本、多次生成任务和多份素材，一次生成也可覆盖多个镜头。
4. 已交接版本可追溯。修改产生新版本，保留此前交接与采用依据；临时工作稿不必每次编辑都归档。
5. 正式下游执行绑定实际使用的剧本、资产、分镜及附件版本，不能仅写“最新版”。
6. 版本不代表采用。新版可以是候选；旧版可继续作为特定已生产镜头的有效依据。采用范围和版本明确记录。

具体编号格式在目录与最小台账设计时统一确定，不在此预设复杂编码。

## 03 任务与交接（已确认）

1. 开始前说明任务目标、范围、输入版本、预期成果、限制与验收条件。
2. 按依赖决定开工范围。缺少关键输入的部分等待，不受影响的工作继续；不能将部分就绪记为全部就绪。
3. 提交实际成果：文件或任务结果、版本、位置、自检结论及已知限制。计划产物不能当成已完成。
4. 接收方打开成果并核对下游需要，记录接收、限定接收或退回及原因。
5. 退回明确问题位置、依据、影响和期望修正，交回对应责任环节。
6. 交接不替代用户采用确认。专业接收仅说明相应范围可以继续使用；用户的关键确认及最终采用权保持有效。

任务进度、接收结论和采用状态分别记录。已提交不等于已接收，已接收不等于批次已获准开工。可在现有任务条目中维护，不强制每次另建交接文档。

## 04 质量检查（已确认）

1. 标准来自项目目标。公共规则规定检查方法，各阶段明确具体合格条件，不以笼统感受代替依据。
2. 结论绑定对象版本与观察范围。明确检查内容及全检或抽查；抽查不写成全检。
3. 证据对应实际检查。文本、静帧、声音、运动、组接和交付分别检查；静帧通过不证明视频运动合格。
4. 专业自检、下游接收检查、整集检查各负其责，如实记录；自检不冒充独立复核。
5. 问题说明位置、依据、影响及建议处理去向，区分阻断使用的问题与可保留的改进项。
6. 修订后检查修改点及关联影响。新版本不自动继承旧版通过结论，无关检查不必全部重做。

检查结论：未检／通过／限定通过／需返工。限定通过须明确可用范围与限制。

质量结论与采用决定分开。通过不替代用户采用权；用户决定保留已知问题时仍保留问题记录，不将其改写为检查通过。

## 05 预算与工时（已确认）

1. 估算、获准投入上限、实际消耗分别记录；预计花费不等于获准投入。
2. 估算说明制作规模、质量要求、工具条件、重试假设、不确定性及范围，避免虚假精确。
3. 统计研究、开发、资产、生成重试、后期、检查和返工的完整投入，区分人工工时、平台等待与整体周期。
4. 共享资产、会员、额度与单项消耗分别记录；共用成本分摊注明口径，同一投入不重复计入总额。
5. 样段及首批制作后，根据实际费用、工时、采用率及返工更新剩余估算。
6. 预计超出已确认费用或时间边界、反复失败或目标变化时，提交影响及备选方案，不自动追加投入。

具体项目再确定预算、周期、预警线与重试上限，不设置通用金额或次数。已获授权范围内的常规执行无需重复确认；新增投入按对应权限处理。

## 06 变更与中断恢复（已确认）

1. 先定位变更来源：改什么、原因、依据及是否需要用户确认。
2. 找出直接使用者及下游，分别判断保留、复核或返工，不默认全部重做。
3. 从最早失效位置修正：剧情回剧本，身份回资产，组接回时间线，避免只修表面。
4. 记录旧新版本、变更决定、影响对象及处理结果，不静默覆盖已交接依据。
5. 中断时保留当前阶段、实际成果、任务状态、未决项与下一步；远端任务保留任务ID。
6. 恢复前检查现有记录及远端结果，再继续执行；状态未知时不直接重复提交或付费重试。

常规变更按已授权范围推进；涉及关键创作、资源边界或已采用成片时，回到对应确认关口。
