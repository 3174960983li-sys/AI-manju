# 整体协作架构

版本：v1.0｜日期：2026-10-31｜状态：整体架构已确认；尚未完成实际生产验证

## 一、已确认的推进方式

整剧规划后分批开发与制作。先完成整剧大纲与分集结构，开发首批单集剧本并验证样段，再分批正式制作；后续单集在整剧基准内滚动开发。

后续变更涉及世界观、人物主线、核心身份或统一风格时，评估对既有成果的影响，再决定保留、复核或返工。

## 二、已确认的用户权限

1. 每一批正式开工由用户确认。总控准备本批范围、依据、就绪情况、资源需求及风险，提交后等待明确确认，不以沉默或上一批确认代替本批确认。
2. 每集成片采用权由用户保留。可以集中审看、集中反馈，但采用结论必须分别对应单集及实际版本。
3. 集中反馈不等于整批全部采用。未明确结论的单集保持待确认；对部分范围的确认不能扩展为全片采用。
4. 常规修订在已确认范围内推进；重大创作或资源变化回到相应决定节点。已采用成片发生修改后，受影响内容重新提交确认，保留旧版采用记录。
5. 批次开工与成片采用均不自动包含外部发布、发送或超出既定授权的付费调用。

## 三、内容层级与共享支撑（已确认）

| 层级 | 管理内容 |
|---|---|
| 整剧 | 目标、受众、制作规格、世界观、人物主线、整剧结构、统一风格、资源边界 |
| 单集 | 剧情推进、人物变化、开场结尾、剧本、制作需求、时间线及前后集状态 |
| 场次 | 戏剧目的、人物知情、目标行动、冲突转折、时空、表演与调度 |
| 镜头 | 画面、动作阶段、声音、摄影、关键图、源素材和采用区间 |

跨层维护共享资产库与制作任务记录。镜头与生成任务分开：一个镜头可多次生成，一次生成可覆盖多个镜头。资产统一维护，具体任务引用所用版本与状态。

## 四、职责结构（已确认）

| 职责 | 工作边界 |
|---|---|
| 用户／项目负责人 | 目标、立项、关键创作、资源上限、重要变更及最终采用 |
| 制作总控 | 组织依赖、任务、交接、进度、成本及变更影响，提交决策建议 |
| 专业创作与执行 | 完成研究、文学、导演、美术、分镜、声音、生成及后期成果，承担本专业自检 |
| 质量检查 | 按实际观察范围检查内容、连续性、组接及技术交付，定位问题并复核 |

职责不等于独立Agent数量。不得将自检冒充独立审查。成果交接以实际文件、采用依据、限制和接收结论为准。

## 五、已确认保留的四个前期关口

用户已确认保留以下四关口，由用户作出相应决定：

| 关口 | 核心确认内容 |
|---|---|
| 项目立项 | 目标价值、可行性、预计投入、主要风险与是否进入正式开发 |
| 整剧创作基准 | 整剧大纲、分集结构、人物主线、世界观与制作规格 |
| 首批创作方向 | 首批剧本、核心参考和导演方案 |
| 生产基准 | 样段效果、核心资产方向、生产路线及修订后的预算周期 |

生产基准通过不替代逐批开工确认。建议决策包包含实际成果、推荐方案、目标差距、未决问题和具体决定项；其详细格式在公共规则阶段确定。

批次大小不预设固定集数，根据资产复用、场景依赖、风险和资源确定。

## 六、单集审看与交付闭环（已确认）

正式开工 → 制作与持续剪辑 → 专业自检和整集检查 → 用户逐集审看 → 定向修订与复核 → 用户采用对应完成版 → 技术输出及交付检查 → 最终交付验收 → 归档。

审看可以按批集中进行，采用结论仍绑定每集实际版本。粗剪或临时声音版本只能获得对应范围的意见与确认，不能当成最终完成版采用。

成片内容采用确认作品表达；交付验收确认实际文件、规格、版本及交付范围。两者可同轮处理，但分别记录。最终交付验收不等于外部发布授权。

返工按以下职责回流：剪辑节奏回时间线；镜头运动或形变回视频制作；身份和空间错误追溯资产或镜头输入；剧情含义变化回剧本与导演依据。由总控定位最早失效环节，保留无关成果。

常规修订在已确认范围内执行；重大创作或资源变化提交用户决定。修订后复核修改点及相邻连续性，交付文件另检查实际导出结果，不重复无关的全部检查。

## 七、已确认的三条协作边界

1. 批次仅用于组织生产，可按场景、资产和资源安排多集任务；不替代单集故事结构与逐集采用记录。
2. 总控负责组织、识别冲突与安排处理，不替代专业创作决策。问题回到对应专业依据，重大取舍由用户决定。
3. 质量检查贯穿制作：专业自检、下游接收检查与整集检查分别履行职责；自检与独立复核如实区分，不因职责名称而宣称具备独立性。
