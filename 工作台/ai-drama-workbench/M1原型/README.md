## 实际验证

1. 左侧填写项目名“我的第一部短剧”，点击创建项目。
2. 创建一个UTF-8的TXT，例如两行“第一场 门厅 夜”和“林禾：谁在外面？”。
3. 选择TXT，点击“读取并保存剧本”，确认页面显示正文、字符数与编码。
4. 再上传包含段落和表格的DOCX，核对段落与表格顺序是否正确。DOCX仅提取正文，文本框、页眉页脚、批注、修订和图片文字可能遗漏。
5. 再次导入同一文件，应提示已有记录；相同文件名不同内容会保留新记录，不覆盖旧稿。
6. 创建第二个项目，应看不到第一个项目的剧本。
7. 停止应用并重新启动，检查项目与剧本仍在。

TXT自动编码只是一种读取策略，不保证所有无BOM文件都能正确判断。遇到乱码，请手动选择正确编码并对照原件。本轮不覆盖同一原件的既有编码解析，编码不同会提示先核对。

文件最大5MB。DOCX解压内容另限30MB。旧DOC需先在Word另存DOCX；空白或损坏文件会给出提示。

## 按SOP使用本轮新增功能

1. 选择项目后，左侧“工作阶段”可以切换已确认的12阶段；默认进入03剧本工作区。
2. 在01、02等阶段填写“阶段准备记录”，点击保存。记录相互独立，不会自动变为立项通过或用户采用。
3. 切换03，导入或选择已保存剧本，点击“模拟拆分并保存场次”。
4. 页面明确显示mock-rules-v1及“模拟结果／待人工核对”。规则优先识别“第一场 内景 门厅 夜”、带空格的“1-1 地点 时间”和INT./EXT.标题。无法识别时，全文作为一个待核对片段保存。
5. 查看场次表和逐场原文。地点、时间及人物只作简单规则提取，摘录不是AI剧情概括，不替代真正逐场分析。
6. 重复模拟会保存新的独立拆分记录，可以切换查看，不覆盖原文或旧结果。关闭后重新启动，记录仍在。

新增业务逻辑阅读顺序：workflow.py（流程映射）→ scenes.py（可替换接口、模拟实现及校验）→ scene_service.py（拆分与事务保存）→ db.py（存储）→ app.py（交互）。

输入正文按场次完整覆盖，source_start/source_end是Python字符区间，左闭右开，不是字节偏移或Word页码。每条拆分记录绑定具体剧本ID和原件SHA-256。

数据库从v1增加到v2，仅新增表；遇到v1会先生成同目录manju_m1.before-v2.sqlite3备份，再创建阶段记录、拆分批次和场次表。旧项目、原件及正文保留。不支持用旧版程序打开升级后的数据库。

本轮只提供模拟provider；业务入口拒绝mode不是mock的provider。场次修改、修订保存和导出已经实现；接下来用实际样例验证字段，真实模型接口和付费测试另行确认。
## 人工修订与导出

在03阶段导入并模拟拆分后，进入“4. 人工修订与导出”：

1. 在“场次版本”选择原始结果或某个历史修订。
2. 选择要修改的场次，调整标题、内外景、地点、时间、人物及分析备注。
3. 原文、字符区间、场次ID和顺序只读；本版不增删、合并或重排场次。
4. 填写修订说明，点击“保存本场为新修订”。每次保存产生完整的新修订快照，不覆盖旧结果。
5. 可基于历史版本保存新的修订。历史版本仍可选择查看；保存不会自动代表质量通过或用户采用。
6. 点击导出JSON或CSV。只导出选中的已保存版本，不导出表单中的未保存修改。

JSON包含来源项目、剧本、拆分记录、修订信息、SHA-256及完整场次。CSV采用UTF-8 BOM，保留来源字段；以公式符号开头的文本会增加单引号，避免被Excel当公式执行。需要原值时使用JSON。

数据库当前为v3，新增scene_revisions表；旧版升级前保存before-vN备份，保留原有项目、原件、模拟记录和场次。并发保存时检查最新修订，拒绝过期写入。新模块：revisions.py负责校验、保存和导出；ui_scenes.py只负责Streamlit交互。

本轮47个测试通过，覆盖人工修改、历史保留、旧版数据、原文不可改、过期保存、跨项目拒绝及中文导出。真实模型仍未接入，原SKILL不变。
## 整体框架工作区

左侧“工作区”提供五个入口：

- 项目总览：12阶段进度、任务交付数量、待确认事项，以及快速进入各阶段。
- 阶段工作区：每阶段的输入、关注点、输出、能力映射、准备记录及任务交付入口；03保留已实现的剧本功能。
- 任务与交付：当前阶段新增记录，全项目查看和编辑记录，分别维护任务进度与交付物采用状态。
- 确认中心：项目立项、整剧创作基准、首批创作方向、生产基准、本批开工、单集成片采用和最终交付验收。范围中明确整剧、批次或单集及具体版本；每个范围单独建记录。
- 规范索引：只读查看本机手册、架构、公共规则及专业职责映射，不改写或执行SKILL。

保存已接收任务需实际成果位置及检查依据；采用交付物和非待确认的关口决定须本人勾选确认。保存记录会保留历史快照，过期版本写入被拒绝。阶段进度为人工记录，不从文件数量、任务接收或关口决定自动推导。

本轮搭建的是统一操作框架，不是完整生产平台。四层结构中单集／镜头专用管理、共享资产、预算工时、任务依赖自动检查和工具执行仍待完善；媒体生成、登录、支付和生产部署不在当前范围。
