# 映序 · AI短剧个人工作台 v0.3

## 启动与停止

访问 http://127.0.0.1:4317 。如果服务尚未运行，双击“启动工作台.cmd”并保持窗口开启；关闭该窗口停止本次服务。开发时启动的隐藏后台服务可运行“停止后台工作台.ps1”停止，其会核对记录的进程是否确为本工作台。

也可在本目录运行 node server.mjs；需要Node.js 20及以上，无需安装依赖。

## 使用顺序

1. 新建项目，在12阶段流程里记录整剧构想与阶段成果。
2. 进入“故事与镜头”，建立单集、场次和镜头，可编辑归属及文字内容。
3. 在“共享资产”建立角色、服装、场景、道具或声音主档，登记版本、状态和资料位置。
4. 编辑镜头，选择共享资产并填写该镜头实际引用的版本和状态。主档变化不会覆盖镜头引用，页面提示差异；差异不自动判为错误。
5. 在“审核中心”创建批次，选择涉及单集，填写范围、就绪依据、资源和风险，提交待确认，由你记录本批开工决定。
6. 登记每集成片的版本、文件或工程位置和已知限制，再记录逐集采用或修改意见。这里只记录，不代表软件已经观看真实视频。
7. 定期导出JSON备份。导入会替换全部项目，需要页面确认。

整剧资料可在项目模块的“编辑项目资料”中修改。内部对象ID与自动编号不随名称修改而改变。当前按创建顺序显示，不提供重排、删除或自动生成。

## 记录与版本边界

数据写入根目录“制作项目/工作台数据/projects.json”；每次写入前保留上一份projects.json.bak。旧v0.1项目可直接读取，首次修改时补充制作资料字段；schemaVersion保持1，以兼容既有备份。

确认记录保存当时的范围或成片版本快照。批次范围、涉及单集及其剧情摘要变化时，旧开工决定显示为待重新确认；成片版本、位置或说明变化时，当前版本显示待采用，历史决定仍保留。

镜头绑定资产版本只是关联记录，不是旧资产文件的自动归档。不能通过修改同一成片文件却保留原版本名来获得真实的内容追溯；需要你准确登记新版本。资料路径仅作为文本保存，软件不读取、上传或验证素材文件。

阶段确认、批次开工、逐集采用分别记录，不相互替代。当前不自动检查所有开工依赖，也不将记录状态当作质量通过。

## 限制与后续

单人本机版本，不支持多客户端同时编辑；只监听127.0.0.1，无账号及用户隔离。公开网站前需增加认证、项目权限、数据库、并发控制、文件存储及部署配置。

尚未接入模型、SKILL自动执行、生成平台、真实媒体预览、任务队列、成本台账或完整版本库。规范库按原文只读展示。未来优先补任务管理、阶段引导和媒体资料体验，再明确模型与平台接口。

## 验证

运行 node --test tests.mjs 。自动测试覆盖保存恢复、备份、无效导入、本机请求限制、四层关联、资产引用及审核换版；测试使用临时文件，不触碰正式项目。浏览器隔离验收另覆盖实际创建、编辑和审核操作。
## v0.3：任务中心与阶段引导

12阶段页新增输入、交付和四项结构化问题，保存与切换会同时保留引导内容及原工作稿。内容是首版填写草案，不代表所有阶段SOP已完成。确认记录保留当时引导与文稿快照，可展开查看。

点击“建立本阶段任务”可以带入阶段及默认依据；应按实际任务补充名称、具体输入版本、验收条件和负责人。任务可关联整剧、单集、场次、镜头、资产或批次，也可以引用同项目内的依赖任务。

任务流程：待开始 → 进行中 → 待接收 → 已接收；问题可退回返工。开始需要输入与验收条件，提交需要实际成果和自检证据，接收前应打开实际成果核对。软件只记录人工操作，不验证资料路径或媒体内容。

未接收的依赖会阻断开始、提交及接收；不允许自身依赖或循环依赖。已接收任务或其依赖发生变化时，受影响的接收结论显示待复核。修改任务重新从待开始推进，保留历史快照；不会自动运行Agent或重做素材。

任务页支持按阶段与状态筛选。当前所有操作仍由个人在本机完成；负责人是记录字段，不会自动发送通知或分配给外部人员。每项目最多2000项任务，超出该规模前应升级存储与依赖查询方式。
